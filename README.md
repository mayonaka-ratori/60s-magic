# はじまりの魔法：最初の24秒

設計仕様の最初の一回を遊べる試作です。簡単な遺跡と一体の騎士を使い、本人の線と言葉から魔法をつくります。防御の回、最後の魔法、魔導書、QR、展示の連続運転は次の段階です。

## 起動する

新しい背景と術式を24秒の本編へ組み込みました。14〜17秒で本人の線を完成形へ収め、17秒から放出し、騎士の胸で光が広がります。騎士は背景から分けた画像を使い、待機、ひるみ、構えを戻す姿勢を切り替えます。最後は結果の枠内に本人の術式を表示します。立体の騎士への置き換えはまだ残っています。

見た目だけを比べる画面は [http://localhost:5173/?view=look](http://localhost:5173/?view=look) です。「見本と並べる」「自分の線で試す」で確認できます。[作った範囲と確認](docs/見た目の確認画面.md)。

Node.js 22.12以上とChromeを使います。プロジェクトのフォルダーで実行してください。

```powershell
npm ci
npm run setup:assets
npm run setup:speech
npm run dev
```

[http://localhost:5173](http://localhost:5173) を開きます。まず「マウスで試す」を選び、「魔法をつくる」を押すと遊べます。機器の準備が終わると「詠唱の準備を始めよ」と3秒の合図が出て、手やマウスの位置を決めてから24秒が始まります。この3秒は24秒にも60秒にも含めません。押したまま動かすと線が残り、手を離した後も描き足せます。画面右側の欄には、声の代わりに言葉を入れられます。

「手で描く」はカメラの許可と手の認識の読み込みを終えてから開始します。片手でも両手でも描けます。手のひらの中央を使い、指の形を決める必要はありません。カメラ映像は送信せず、このPC内の別の処理場所で認識します。認識に必要なファイルは `setup:assets` で一度取得します。

「見本の動きを見る」は操作なしの見本です。本人の入力の確認には数えません。

「効果音」で音を使うか選び、「音を試す」で確認できます。初期音量は25%です。プレイ中も「音を消す」で止められます。マイクを使う回は14.75秒まで効果音を鳴らしません。[騎士の動きと効果音の説明](docs/騎士の動きと効果音.md)。

音声認識は、このPC内で動く設定です。「マイクで唱える」にチェックを入れ、マイクの使用を許可してください。Googleの契約やAPIキーは不要です。最初は「マウスで試す」と組み合わせ、「氷よ、壁となれ」「雷よ、七つに分かれろ」を試せます。

## 作った範囲

| 時刻 | 動作 |
| --- | --- |
| 0〜6秒 | 手に追従する線。声も受け付ける |
| 6〜11秒 | 元の線を保ち、光点と短い接続線を追加 |
| 11〜14秒 | 描きながら詠唱。最後まで線と言葉を受け付ける |
| 14〜14.7秒 | 描画と録音を締め、文字の最終結果を待つ |
| 14.7〜15.7秒 | 動きと言葉を一回の要求でJevへ送る |
| 16秒 | 魔法の内容を固定。以後の回答は使わない |
| 14〜17秒 | 線に光が巡り、中心へ集まり、完成する |
| 17〜23秒 | 本人の術式から放出し、騎士へ作用して余韻を残す |
| 23〜24秒 | 戦闘中の線と光を収め、一回目の終わりを見せる |
| 24秒以降 | 魔法名、詠唱、短い感想の入力、確認用の記録 |

元の点列と表示用の点列を分けています。表示だけ手ごとに256点へ間引き、元の点列は残します。認識が150ms以上途切れた場合と大きく位置が飛んだ場合は筆を分けます。止まったことを受付終了の条件にはしません。小さい動きは、入力を終えた後の完成演出で拡大します。

球・線・壁・結界・波・複数弾を用意しました。雷は枝分かれ、氷は結晶など、色と形を変えます。明示した個数は最大8つです。初回の防御の言葉は騎士の前へ広がる壁、拘束は騎士を囲む線、強化は力の波として見せます。いずれも一回目の魔法の作用で、二回目の防御場面ではありません。

術式と魔法は入力から描画します。現在の騎士は生成した3つの姿勢の画像を使って動かします。効果音はブラウザー内で合成します。立体の敵、床や鎧へ届く照明、音楽は未制作です。

## Jevと音声認識をつなぐ

PC内の音声認識だけなら `.env` は不要です。JevやGoogleを使う場合は、まだ `.env` がなければ `.env.example` をコピーして、接続情報を自分のPCで設定します。秘密の値を画面やチャットへ貼る必要はありません。設定後は起動し直してください。

```powershell
Copy-Item .env.example .env
```

### このPCでの音声認識（初期設定）

Kotoba-Whisper v2.0をfaster-whisperで動かします。Pythonの準備に使う [uv](https://docs.astral.sh/uv/getting-started/installation/) が必要です。WindowsとNVIDIAのGPUの組み合わせ（RTX 4070 SUPER 12GB）で動作を確認しました。NVIDIAのGPUがないPCやMacではCPUで動きます。CPUでKotoba-Whisperを動かすと一回の認識に約5秒かかり（10コアのMacで実測）、14秒の詠唱に間に合いません。そのためMacでは初期値を小さい `small` モデルにしています。日本語の聞き取りは粗くなりますが、短い詠唱の言葉を数秒以内に返すことを優先します。`.env` の `LOCAL_SPEECH_MODEL_ID` で `medium`、`base`、`kotoba-v2.0` に変えられます。変えたら `npm run setup:speech` をもう一度実行します。CPUでは一回の認識に時間がかかり、14.7秒までに最後の結果が届かない場合があります。その場合は、それまでに届いた最後の途中結果を使います（PC内の認識は毎回それまでの音を全部聞き直すので、途中結果でも一続きの文になっています）。結果の画面に「途中の聞き取りを使用」と出ます。プレイ中は画面左下に聞き取った文字を出します。使うCPUの数は `LOCAL_SPEECH_THREADS` で変えられます。Macでの速度は未確認です。

`npm run setup:speech` で必要なソフトと認識用ファイルを取得し、起動まで確認します。WindowsではPowerShell、MacとLinuxではbashの手順が自動で選ばれます。初回は数GBの空き容量と通信が必要です。Python 3.12と必要なソフトは `.venv-speech`、認識用ファイルは `.local-speech/models/kotoba-v2.0` に置きます。PC全体のPythonや設定は変更しません。これらの大きなファイルはGitには含めません。

一度取得すれば、認識処理は通信なしで動きます。サーバーの起動時に読み込みを終え、画面に「このPCで認識」と出たらマイクを選べます。声はこのPCから外へ送らず、録音ファイルにも残しません。認識結果の文字と動きの特徴は、Jevを設定した場合だけJevへ送ります。

14秒までの声を一時的に保持し、約0.65秒ごとに更新します。14秒で受け付けを終え、最後の結果を待ちます。110〜125ミリ秒という確認値は合成音声一回分の認識処理の時間で、話してから表示されるまでの時間ではありません。長い詠唱、人の声、周囲の音がある場所は別に確認が必要です。

同時に音声認識を使える画面は一つです。認識が止まった場合はアプリを起動し直してください。Googleへ自動で切り替わることはありません。`.env` を使う場合も `SPEECH_PROVIDER=local` のままで利用できます。通常は `LOCAL_SPEECH_PYTHON` と `LOCAL_SPEECH_MODEL` を空欄にします。GPUとCPUは自動で選びます。強制したい場合だけ `LOCAL_SPEECH_DEVICE` に `cuda` か `cpu` を設定します。

### Jev

`JEV_API_KEY` を設定します。モデルは仕様書に合わせて `jev-1.13.0` を初期値にしています。契約先で利用できる版を確認し、必要な場合だけ `JEV_MODEL` を変更してください。

サーバーから `https://api.typesafe.ai/v1/systemone` へ、属性・用途・形・進み方の4問、守る性質・広さ・持続・集中の4問、囲う・分裂・前回との関係・動きと言葉の一致の4問を送ります。同じ入力を独立した12問で評価します。秘密の値はブラウザーに送りません。

返された候補の確率、次点との差、数値の範囲を確認します。明示した肯定の言葉を優先します。曖昧な項目はその項目だけPC内の規則で補います。採用した項目と理由を記録します。初回には前の魔法がないため、その質問で前の形を追加することはありません。

未設定・混雑・切断・遅延でも演出は延長しません。サーバーは900msで打ち切り、ブラウザー側も15.7秒で打ち切ります。自動の再試行はしません。遅い回答、別のプレイ番号、別の入力版は魔法に使いません。

### Google Cloud Speech-to-Text V2

Google Cloud側でSpeech-to-Textを利用できるようにし、実行するアカウントに音声認識の権限を付けます。次を `.env` に設定します。

- `SPEECH_PROVIDER=google`：Googleの認識へ切り替える場合だけ設定
- `GOOGLE_CLOUD_PROJECT`：プロジェクト番号ではなくプロジェクトID
- `GOOGLE_CLOUD_LOCATION`：初期値は `us`
- `GOOGLE_APPLICATION_CREDENTIALS`：認証用JSONファイルの絶対パス。既にPCの標準認証を設定している場合は不要

Googleについて、画面の「接続の確認」は設定の有無を示します。接続が成功したという表示ではありません。設定後に「マイクで唱える」を選び、実際に声を出して確認してください。

GoogleではChirp 3、日本語、共通の詠唱辞書から作った語句補助を使用します。

### 両方の認識で共通すること

実際のマイクの入力周波数をもとに16kHz・一チャンネルのPCMへ変換します。発話前の0.3秒と短い余白を含めて、0.1秒程度ずつこのPCのサーバーへ送ります。短い無音で受付を終えません。音量は波形と光の動きにのみ使い、威力には使いません。波形は声を受け取ったことを示すもので、文字に変換できたことの保証ではありません。

周囲の声と本人の声を完全に分ける機能ではありません。口元へ近づけたマイクで確認してください。認識した文字の時刻は送信した音の時刻へ戻し、結果が届いた時刻と混ぜません。安定した途中結果か確定結果のみを使います。

録音はファイルへ保存しません。カメラ映像も保存しません。外部サービス側の保存は各契約の設定に従います。「記録を保存する」を押した場合だけ、詠唱・動き・魔法の内容・Jevの回答・感想に加え、声が届いた時刻や描画の遅れなどの確認用の記録をJSONへ保存します。中止した回は開始画面の「前回の記録を保存する」で保存できます。見方は [確認用の記録の見方](docs/確認用の記録の見方.md) にあります。この試作には公開ページや自動アップロードはありません。

## 確認する

開始画面の「詠唱の言葉を見る」で110語の読み方と詠唱例を確認できます。辞書、参考資料、難語の聞き取りで残った問題は [詠唱辞書と認識の確認](docs/詠唱辞書と認識の確認.md) にまとめました。音声認識へ渡す単語を増やすと悪化したため、実行時の手掛かりは元の14語を維持しています。

```powershell
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

ブラウザーの試験では、一回分の進行、途中からの描き足し、最後の入力、遅い回答の破棄、カメラの認識ファイルの起動、中止を確認します。カメラの試験はブラウザーが生成した映像を使います。実際の手の精度を証明する試験ではありません。

ローカルの音声認識そのものを確認する場合は、次を実行します。Windowsの日本語の合成音声を使い、氷の壁、七つの雷、言い直し、攻撃しない指示を各3回と、無音を確認します。続けて、終了直前の声がゲーム内の発動まで届くことをブラウザーで確認します。

```powershell
npm run test:speech
node scripts/prepare-browser-audio.mjs
npx playwright test tests/browser/local-voice.spec.ts
```

確認用の合成音声と結果は `.local-speech` に置きます。人の録音ではありません。認識用のファイルが未取得のPCでは音声の試験はできず、ブラウザーの音声試験は確認用の音がなければ省略します。

人に試してもらう手順は [docs/最初の24秒_確認手順.md](docs/最初の24秒_確認手順.md) にまとめています。
今回の結果と未確認事項は [docs/実装と確認の記録.md](docs/実装と確認の記録.md) をご覧ください。

配布用の画面を使う場合は次のように起動します。同じサーバーが音声とJevの接続も担当します。

```powershell
npm run build
npm start
```

初期設定では自分のPCからだけ開けます。別の端末から使う公開方法や展示の運用は、第三段階で扱います。

## ファイル

- `src/game/`：時計、手の軌跡、発話の更新、魔法の決定
- `src/input/` と `public/*worker*.js`、`public/audio-worklet.js`：カメラとマイク
- `src/render/`：Babylon.jsの背景・仮の敵、画面手前の術式と魔法
- `server/`：接続情報を持つサーバー、Jevの12問、PC内とGoogleの音声認識
- `speech/`：PC内の音声認識、使用するソフトとモデルの版の固定
- `tests/`：進行・入力・回答の検査、音の取り込み、ブラウザーの試験

日本語表示にはPCへ同梱したNoto Sans JPとNoto Serif JPを使います。実行時に外部のフォント配信へ依存しません。手の認識の版とモデルの確認値は `public/vision/version.json` に残します。
