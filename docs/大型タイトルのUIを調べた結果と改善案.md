# 大型タイトルのUIを調べた結果と、この画面の改善案

モンスターハンター、エルデンリングなどのUIを調べ、読みやすさの公開基準と突き合わせて、
この試作の画面をどう直すかをまとめました。

調べ方はウェブ検索です。この環境では外部サイトへの直接の読み込みが遮断されていたため、
検索結果に含まれる本文を根拠にしています。出典は各項目に付けました。
原文の確認が必要な発言は、リンク先で見直してください。

あわせて、今の画面の文字の大きさと、背景とのコントラストを実測しました。

---

## 1. 調べて分かった傾向

### 1-1. 情報は四隅へ、中央は空ける

モンハンは左上に体力とスタミナ、右上にミニマップ、右下にアイテム、左下にモンスターの
アイコンを置き、画面の中央を空けています。プレイヤーが見るのは中央なので、
そこに文字を置かない作りです。ライズだけは翔蟲のゲージを下中央に置いています。

出典：[Prima Games](https://primagames.com/tips/monster-hunter-world-understanding-hud)、
[カプコン公式マニュアル](https://manual.capcom.com/mhwilds/en/ps5/page/3/9/)

### 1-2. 常に出すものを絞り、あとは必要な時だけ出す

エルデンリングが常時出しているのは、左上の体力・FP・スタミナの3本、右下の装備、
上中央の方位磁石だけです。ミニマップも目的地の印もありません。
HUDの表示を「オート」にすると、方位磁石以外は自動で消え、減った時だけ現れます。
歩いている間の画面はほぼ風景だけになります。

モンハンのワイルズも同じ考え方を設定で選べます。ゲージを常に出す「Fixed」と、
変化した時だけ出す「Dynamic」の切り替えがあります。

出典：[Elden Ring Wiki: HUD](https://eldenring.fandom.com/wiki/HUD)、
[Game UI Database](https://www.gameuidatabase.com/gameData.php?id=1371)、
[Icy Veins](https://www.icy-veins.com/monster-hunter-wilds/news/best-settings-to-improve-your-monster-hunter-wilds-experience/)

### 1-3. 敵の状態は、数字ではなく見た目で伝える

モンハンは20年以上、モンスターの体力を数字でもバーでも出していません。
足を引きずる、巣に帰る、オトモが「弱ってるニャ」と言う、瀕死で心音が鳴る、といった
見える変化で伝えます。ワイルズでは、攻撃を集中させた場所に傷が残り、狩りが進むほど
見た目がボロボロになります。ロックオンすると心拍の波線が出て、満タンは青い大きな波、
弱るほど黄から赤になり、波が小さく遅くなります。

出典：[PlayStation LifeStyle](https://www.playstationlifestyle.net/2018/02/22/argument-against-monster-hunter-health-bars/)、
[Game Rant](https://gamerant.com/monster-hunter-mh-wilds-focus-mode-strike-wounds-explained/)

### 1-4. 山場の直前に画面を空にし、大きな文字ひとつで決める

エルデンリングは霧をくぐると戦闘が始まり、下中央に細い体力バーとボス名が出ます。
倒すと画面全体に金色の大きな文字が一つだけ出ます。敵の格で言葉が変わり、
ENEMY FELLED、GREAT ENEMY FELLED、LEGEND FELLED、GOD SLAINと重くなっていきます。
死ぬと暗い画面に赤い「YOU DIED」がゆっくり浮かびます。SEKIROは漢字一文字の「死」です。

印象に残る理由は単純で、ほかの情報を全部消した画面に、大きな文字を一つだけ、
急がずに出すからです。

出典：[Fextralife](https://eldenring.wiki.fextralife.com/Bosses)、
[Know Your Meme: YOU DIED](https://knowyourmeme.com/memes/you-died)

### 1-5. 文字の大きさには公開された数値がある

- Xboxのアクセシビリティ指針（XAG 101）：1080pで**最小28px**。さらに26pxから52pxまで
  変えられること。これは3m前後離れて見るテレビを想定した値で、目標ではなく下限です。
- Game Accessibility Guidelinesも28pxを基準にしています。
- 字幕はもっと大きく、1080pで**46px以上**が推奨（英Channel 4のHD字幕基準と同じ値）。
- ISO 9241-303は視野角で定義していて、大文字の高さが最小16分、推奨20から22分。
  距離が変わっても使える基準です。
- 任天堂とソニーは公開の数値指針を出していません。数値が要るならXboxのものを使います。

出典：[Xbox Accessibility Guidelines 101](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101)、
[Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/use-an-easily-readable-default-font-size/)、
[Ian Hamilton](https://ian-hamilton.com/how-to-do-subtitles-well-basics-and-good-practices/)

### 1-6. 背景の上の文字は、縁取りか帯で守る。影だけでは足りない

- WCAG 2.2のAAは、通常の文字で**4.5:1**、24px以上の大きい文字で3:1。
- Xboxの指針はゲームでも既定で4.5:1を求め、サンセリフ体を指定しています。
- 手法には優劣があり、**影だけは推奨されていません**。文字の片側しか背景から
  分離できないためです。推奨は2px以上の太い縁取り、または黒の半透明の帯
  （不透明度50から70%）。既定としては両方の併用が良いとされています。

出典：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、
[Xbox Accessibility Guidelines 102](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/102)

### 1-7. 説明は、使う瞬間にひとつずつ

先に全部出さず、その情報が実際に使える瞬間に出す（progressive disclosure、
just-in-time）のが定説です。チュートリアルは一度に一つの概念にし、読ませるより
やらせる。ワイルズのチュートリアルは逆のことをして批判されました。
「戦闘中に急に出て時間が止まる」「読み切る前に消える」「結局は消したくて
ボタン連打になる」といった声が出ています。

出典：[UXPin](https://www.uxpin.com/studio/blog/what-is-progressive-disclosure/)、
[Steam Community](https://steamcommunity.com/app/2246340/discussions/0/597392228959148122/)

### 1-8. 残り時間は段階で知らせる

よくある作りは、残り10秒以下で黄から赤へ、5秒以下で拡大と明滅と音、の2段階です。
スーパーマリオは残り100で曲が速くなり、残り30秒でタイマーが赤く明滅して
曲が半音上がります。Counter-Strikeの爆弾は40秒で、残りが減るほど電子音の間隔が
短くなります。

注意点として、タイマーが小さく、視線の外（画面の上など）にあると、時間切れが
不意打ちになります。視線と手がある場所に警告を重ねるのが対策です。

出典：[Mario Wiki: Timer Warning](https://www.mariowiki.com/Timer_Warning)、
[Game Developer](https://www.gamedeveloper.com/design/time-for-a-timer---effective-use-of-timers-in-game-design)

### 1-9. 手応えは100ms以内。音、光、文字の順

0.1秒以内に反応が返れば、自分が直接動かしている感覚になります（Nielsenの3つの限界値）。
入力の遅れは50msを超えると気づかれ始め、100msははっきり分かります。
演出の順番も効きます。まず振動と音で衝撃を作り、次に光と粒、最後に文字や数値。
同時に全部出すより手応えが出ます。

出典：[Nielsen Norman Group](https://www.nngroup.com/articles/response-times-3-important-limits/)、
[Real-Time Collision Detection](https://realtimecollisiondetection.net/blog/?p=30)

### 1-10. 展示は、通りすがりの数秒で何の遊びか分かること

係員の説明が要る時点で参加率が落ちます。回転の速い会場では、20秒程度の挑戦のほうが
深い体験より人数が出ます。古典的な解がアトラクトモードで、無操作が続いたら
自動プレイの映像、得点表、点滅する案内を順に見せてタイトルへ戻ります。
狙いは説明ではなく、まず気づかせることです。

出典：[TV Tropes: Attract Mode](https://tvtropes.org/pmwiki/pmwiki.php/Main/AttractMode)、
[Old School Gamer](https://www.oldschoolgamermagazine.com/arcade-attract-mode-and-the-rise-of-modern-gaming-promos/)

### 1-11. 書体は、UIがゴシック、明朝は題字と名前だけ

画面で読む横組みの文字はゴシック体が適していて、明朝体は長文の縦組みや
印刷物に向きます。エルデンリングは明朝に当たるセリフ体を使いますが、
文字を金色にして影と帯を重ね、背景を常に暗く保つことで読みやすさを作っています。
そのうえで「文字サイズを変更できない」「テレビから離れると読めない」という
苦情が多く出ています。

出典：[伝わるデザイン](https://tsutawarudesign.com/yomiyasuku1.html)、
[Can I Play That?](https://caniplaythat.com/2022/02/27/elden-ring-lacking-accessibility-unintentional-barriers-and-land-jellyfish/)、
[Kotaku](https://kotaku.com/elden-ring-ui-ux-user-experience-interface-fromsoftware-1848637410)

### 1-12. 情報を減らしすぎた側の失敗も見ておく

エルデンリングは文字サイズを変えられず、話者名も出ません。ナイトレインは
1回40分の時間制限がある遊びなのに、装備の説明が曖昧で比較に手間がかかる点が
強く批判されています。短い時間の遊びでは、雰囲気のための曖昧な言葉と、
その場で判断するための情報は分けて出す必要があります。

出典：[PC Gamer](https://www.pcgamer.com/games/rpg/fromsoftwares-clunky-ui-and-coy-descriptions-are-keeping-me-from-truly-loving-elden-ring-nightreign/)

## 2. 今の画面を測った結果

### 2-1. 文字の大きさ（1920×1080で実測）

| 場所 | いま | Xboxの下限28pxとの比較 |
| --- | --- | --- |
| 案内の見出し（押したまま、自由に描こう） | 24px | 足りない。設計仕様の「36〜44px」にも届かない |
| ひとこと（止まっても、また描き足せます） | 12px | 半分以下 |
| 進み具合（線を描く／形になる／放つ） | 11px | 半分以下 |
| 敵の名前（遺跡の騎士） | 13px | 半分以下 |
| のこり秒の数字 | 34px | 足りている |
| のこり秒の「のこり」「秒」 | 12px | 半分以下 |
| 文字入力の見出し | 12px | 半分以下 |
| 中止する／音を消す | 12px | 半分以下 |

見出しの24pxは、`src/cast-style.css`の`.instruction{font-size:24px}`が
`src/style.css`の`clamp(24px,2.3vw,44px)`を打ち消しているためです。
1920でも24pxのまま止まっています。設計仕様（1.4）は
「1920×1080では操作指示を36〜44px相当から検証する」と書いているので、仕様とも食い違います。

### 2-2. 背景とのコントラスト（1440×900で実測。背景の明るさの中央値に対する比）

| 場所 | 比 | 判定 |
| --- | --- | --- |
| 案内の見出し（暗い帯の上） | 13.1:1 | 十分 |
| ひとこと（暗い帯の上） | 9.0:1 | 十分 |
| 文字入力の見出し（暗い帯の上） | 9.5:1 | 十分 |
| 中止する（薄い帯の上） | 7.8:1 | 十分 |
| 敵の名前（写真の上、影のみ） | 3.5:1 | 4.5:1に届かない |
| のこり秒（写真の上、影なし） | 2.7:1 | 届かない |
| 題字の下の小さな文字（写真の上、影なし） | 2.2:1 | 届かない |
| 題字（写真の上、影あり） | 5.1:1 | ぎりぎり |

はっきりしています。**暗い帯の上に置いた文字は十分読める。写真の上に直接置いた文字は
足りない。** 影を付けても3.5:1止まりで、これは調査で分かった
「影だけでは足りない」とも一致します。

背景の明るい部分（空や石畳の照り返し）に重なると、さらに下がって1.6〜2.3:1になります。

## 3. 改善案

### A. 文字を基準まで大きくする（優先度：高）

会場の画面はテレビほど遠くないので、28pxを全部に当てはめる必要はありません。
1.5〜2mで見る想定なら、次を目安にします。

| 場所 | いま | 案 |
| --- | --- | --- |
| 案内の見出し | 24px | 36px（1920で。仕様の下限に合わせる） |
| ひとこと | 12px | 18px |
| 進み具合 | 11px | 16px |
| 敵の名前 | 13px | 20px |
| のこり秒の添え字 | 12px | 16px |
| 文字入力まわり | 12px | 16px |

やり方は、`px`の直接指定をやめて`clamp()`で画面幅に追従させるのが確実です。
`.instruction`の24pxの打ち消しを外すだけでも、1920で44pxに戻ります。

### B. 写真の上の文字に、帯か縁取りを付ける（優先度：高）

のこり秒、敵の名前、題字の下の小さな文字に、次のどちらかを付けます。

- 黒の半透明の帯（不透明度50〜70%）を文字の後ろに敷く
- 2px以上の縁取り（`paint-order:stroke fill`と`-webkit-text-stroke`の組み合わせ）

影だけで済ませないのが要点です。帯を敷けば、背景の明るさに関わらず読めます。

### C. のこり時間を段階で見せる（優先度：高）

いまは白い数字が減るだけです。調査で見た作りに合わせて、2段階にします。

- 残り10秒：数字を黄色へ。上の進み具合の線も黄色へ。
- 残り5秒：数字を赤へ、少し拡大。秒が変わるたびに1回だけ明滅する（連続では光らせない）。

さらに設計仕様（1.4）が書いている「締め切りが近づいたら外周の光で残り時間を示す」を
足すと、視線が画面の中央にあるまま残りが分かります。
タイマーが右上にあるだけだと、時間切れが不意打ちになるという指摘があるので、
画面の外周が少しずつ狭まる、といった見せ方を足したいところです。

### D. 発動と結果を、もっと大きく見せる（優先度：中）

エルデンリングの作りをそのまま借ります。

- 17秒の発動の瞬間に、下の案内枠を一度消す。画面を魔法だけにする。
- 魔法名は、下の小さな枠の中ではなく、画面の中央寄りに大きく（60px以上）、
  1秒ほどかけてゆっくり出す。いまは24pxの見出し欄に名前が入るだけです。
- 24秒の結果でも、まず魔法名だけを大きく出し、そのあとに術式の絵と説明を出す。
  いまは全部が同時に出ます。

これは手間が中くらいですが、「自分の魔法を放った」という中心の気持ちよさに
直接効く部分です。

### E. 敵の状態を、バーではなく見た目で（優先度：中）

いまは18.5秒で体力バーが100%から70%へ動くだけです。モンハンの作りに倣い、
騎士の姿の変化を主にします。

- 当たった場所に光の傷が残る（いまも被弾の姿勢はあるので、そこに足す）
- 体力バーは細くして、当たった瞬間だけ出す（当たっていない間は消す）

設計仕様（1.7）も「画面の体力表示を残す場合は演出の進行に合わせて減らす」と
書いていて、バーを主役にしない方向です。

### F. 説明は、使う瞬間にひとつずつ（優先度：中）

いまの開始前の画面には、描き方の選択、マイク、効果音、音量、詠唱の言葉、
説明文が同時に並んでいます。初めての人が読む量としては多いです。

- 最初に見せるのは「魔法をつくる」と、描き方の選択の2つだけにする。
- 音とマイクは、その下に小さくたたむ。
- 「詠唱の言葉を見る」は、いまは開始前にしか出ません。詠唱が始まる11秒あたりに、
  例をひとつだけ画面に出すほうが効きます（「たとえば、雷よ、七つに分かれろ」）。

### G. 触った瞬間の手応えを測る（優先度：中）

100ms以内に反応が返っているかを確かめます。いまは記録に
「手を動かしてから表示されるまでの遅れは未計測」と書いてあり、測っていません。
`src/main.ts`の記録に、入力から描画までの時間を足して確かめるとよいです。

演出の順番も見直します。いまは発動で光と音がほぼ同時です。
音を先に、光をその直後、文字を最後にすると手応えが増します。

### H. 展示のアトラクトモード（優先度：中）

いまは「見本の動きを見る」を押すと見本が動きます。これを、誰も触っていない時に
自動で始まるようにします。30秒ほど無操作なら見本を流し、終わったらタイトルへ戻る。
通りすがりの人が、何をする遊びかを説明なしで理解できます。

### I. 書体を仕様どおりに整える（優先度：低）

設計仕様（1.4）は「日本語表示はNoto Sans JPを基本とし、魔法名のみNoto Serif JPを
使ってよい」と書いています。いま明朝（Serif）を使っているのは、題字、開始前の見出し、
**プレイ中の案内の見出し**、魔法名、小窓の見出し、**敵の名前**です。

魔法名と題字は明朝のままでよいと思います。プレイ中の案内の見出しと敵の名前は、
仕様どおりゴシックへ戻すほうが、遠くから読みやすくなります。
調査でも、画面で読む横組みはゴシックが向くとされています。

### J. ふりがな（優先度：低）

設計仕様（1.4）は「最小PoCでは難読語に小さいふりがなを付ける」と書いていますが、
まだ入っていません。「詠唱」「術式」「遺跡」あたりが対象です。
`<ruby>`を使えば足せます。

## 4. やらない方がよいこと

- **情報を足す方向の変更。** ワイルズは要素を足して「一画面に詰め込みすぎ」と
  批判され、あとから設定で戻せるようにしました。この試作は24秒しかないので、
  足すより減らすほうが効きます。
- **HUDを全部消す方向。** エルデンリングは減らしすぎた側で批判されています。
  1回きりの展示では、読み返しができないぶん、必要な情報は出し続けるべきです。
- **文字を雰囲気だけで選ぶこと。** 明朝で小さい文字は、初見の人が読めません。

---

## 5. 進め方の案

1. **A（文字の大きさ）とB（帯と縁取り）** を先にやります。CSSの変更だけで、
   数値の根拠もはっきりしています。
2. **C（のこり時間の段階）** を次に。見た目と分かりやすさの両方に効きます。
3. **D（発動と結果の見せ方）** はここが一番効きますが、演出の作り直しが要ります。
4. E以降は、防御と最後の魔法を作る段階と合わせて進めるのがよいと思います。

なお、前回の変更で進み具合の表示を「線を描く／形になる／放つ」に直しましたが、
設計仕様（1.4）は「描く・唱える」「術式完成」「発動」と書いています。
どちらを正とするか決めてください。遊ぶ人の分かりやすさなら前者、
仕様との一致なら後者です。

## 6. 調査の制約

この環境では外部サイトへの直接の読み込み（WebFetch）が遮断されていたため、
検索結果に含まれる本文を根拠にしています。数値はいずれも出典元に記載のあるものですが、
開発者の発言の正確な文言は、リンク先で確認してください。

コントラストの数値は、画面を撮って文字の四角形の中の明るさを測り、
その中央値と文字色の比を出したものです。文字そのものの画素も含むため、
明るい側の数値は実際より高めに出ます。中央値のほうを判断に使ってください。
