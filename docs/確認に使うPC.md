## 測った値

### 音声認識（Mac、2026年9月20日）

`whisper-small` をCPUだけで、10コア中5コアを使って動かしたときの一回の認識時間です。ゲームは毎回「先頭から今まで」を聞き直すので、声が伸びるほど時間が延びます。

| 声の長さ | 認識にかかる時間 |
| --- | --- |
| 0.4秒 | 1.07秒 |
| 2.6秒 | 1.07秒 |
| 6.0秒 | 1.20秒 |
| 10.0秒 | 1.57秒 |
| 13.2秒 | 1.70秒 |

声が短くても約1秒かかります。これは声を音の特徴に変える処理で、`chunk_length=15` の設定のぶん、短い声でも15秒ぶんを計算するためです。

モデルの読み込みは1.465秒でした。プレイの2回目に、出だしの認識が4.5秒と4.3秒かかった回があります。前のプレイの演出やカメラの処理とCPUを取り合ったと見ています。

### 描画（Mac）

カメラを使って24秒を通したとき、平均56fps、フレーム間隔の99パーセンタイルは33.7msでした。ただし1コマだけ249ミリ秒かかった回があり、50ミリ秒を超えたコマが5回ありました。音声認識とCPUを取り合った跡と見ています。

### 手の認識

以前はCPUだけで手を探していました。今はまずMacのGPUで試し、使えないときだけCPUへ戻します。CPUだけだと毎秒10〜15コマ、GPUを使うと60コマ以上という報告があります。実際にどちらで動いたかは、確認用の記録の `diagnostics.camera.delegate` で分かります。

`?hands=cpu` を付けて開くと、わざとCPUで動かして比べられます。

### 音声認識（Windows、NVIDIA GPU）

`kotoba-whisper-v2.0` で、合成音声の一回分が約110〜125msでした。

## 速さを自分で測る

準備できているモデルを同じ音声で比べられます。

```
npm run make:speech-fixtures   # 確認用の日本語音声をPC内で作る（Macは say、WindowsはSystem.Speech）
npm run benchmark:speech       # 準備できているモデルを全部測る
npm run benchmark:speech kotoba-v2.0-mlx small   # モデルを選んで測る
```

結果は `.local-speech/speed-report.json` に残ります。14秒ぶんの認識が1.1秒以内なら、最後の言葉が魔法に間に合います。

## 気をつけること

- `mlx`（MacのGPUで動かす仕組み）は Apple Silicon の Mac でしか動きません。Windows と Linux では自動で `faster-whisper` に戻ります。
- 音声認識も手の認識も画面の描画もGPUを使うので、GPUの取り合いが起きないかを次の確認で見てください。
- Linux の作業環境（Claude Code など）では画面の描画がソフトウェア処理になり、ブラウザーの通し試験が時間切れになります。単体の試験と型の確認は通ります。
- 実際の人の声での精度と遅れは、まだ人数を集めて確かめていません。
