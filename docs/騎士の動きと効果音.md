# 騎士の動きと効果音

2026年9月20日。最初の24秒に追加しました。

## 今回の範囲

騎士と背景を別にしました。背景は一枚絵のまま、騎士はアプリ内で組み立てた立体のモデルです。作り方は2通りです。丸みのある部品は、横から見た輪郭の線を1本描いて、それを回して立体にしています（兜、胸、喉当て、肩当て、腰の板、腰布）。輪郭の線に段を付けると、1つの部品で重ね板になります。残りは角柱、円錐、半球です（腿、丸い膝当て、脛当て、先のとがった具足、帯、金の裾、腹、金のV字、胸の核、背中のマント、とがった面、後ろへ寝た角、光る目、肩の棘、上腕、肘当て、前腕、剣、五角形の盾、足元の影）。全部で50ほどの部品です。鎧の模様、指、布の揺れは作っていません。

回して作った部品は、面ごとに平らに塗っています。輪郭は丸いまま、板を張り合わせた鎧に見えます。角柱の面の数も6から12〜20へ増やしました。

形は元絵の騎士へ寄せています。腰は板を3枚重ねてから布が長く広がり、肩は板を重ね、盾は上が広く下がとがった五角形で体の横へ下げています。頭は小さめにし、金は帯、裾、盾の縁と帯、胸のV字だけに使って、広い面には置いていません。盾側の肩当てだけ少し大きくしています。

剣と盾は後から作り直しました。剣は刃が細くて画面の中で線に見えていたので、幅を広げ、先の三角を別の部品にして、柄を両手で握れる長さにし、鍔も横へ伸ばしました。盾は平らな板だったので、手前の面を一回り小さくして縁に斜めの面を作り、中央の帯を角の立った隆起に変え、五つの角へ鋲を置いています。隆起は左右で明るさが変わるため、正面から見ても平らに見えません。

金属に見せるため、空と床の色を塗った小さな絵を6面ぶんアプリの中で作り、鎧、金の縁、刃へ映り込ませています。正面より縁のほうが強く映ります。画像のファイルは持たず、起動時に描いています。あわせて、面が視線に対して寝ているほど明るくなる設定で、逆光の縁を起こしています。この明かりは以前は面の広い範囲へ回っていましたが、本当に縁の部分だけへ絞りました。胸の核と兜の目はにじませ、命中の瞬間だけ胸の前の光源を強めます。この光源の色は魔法の属性の色を白へ寄せたものです。

姿勢は待機、命中でひるむ姿勢、構えを戻す姿勢の3つです。画像を切り替えるのではなく、3つの角度の表を重みで混ぜ、胴、首、剣の腕、盾の腕の4か所を曲げます。腕は肩と肘の2段にして、肘を少し前へ曲げています。

立ち方は左右で変えています。足の位置を前後にずらし、つま先を外へ開き、膝から下を少し内へ向けています。待機中は体がごく小さく上下し、上半身がゆっくり揺れ、首が左右へ振れ、腕も少し動きます。兜の目はゆっくり明滅します。端末の「動きを減らす」設定では、これらをすべて止めます。

背景の一枚絵と同じ大きさに見えるよう、足元が画面の高さの71.4%、兜の先が5.2%に来る視点を固定しています。横長の画面では背景が広がる分だけ視野を狭め、騎士も同じだけ大きくします。光は空からの弱い光、奥からの逆光、手前からの光の3つです。手前の光だけが影を落とし、肩当てや剣、帯の影が体に掛かります。足元の丸い影は、今までどおり濃淡を描いた一枚の面です。

## 表面の傷と汚れ

面がのっぺりしていたので、絵を3枚、起動時にその場で描いて全身へ貼りました。外部のファイルは増えません。

- 汚れ：しみと、縦に流れた跡。材質の色に掛けて暗くします。
- てかりむら：磨けた所と曇った所。光り方の強弱を場所ごとに変えます。
- でこぼこ：打ち傷のへこみ、擦り傷、鋳物のざらつき。白黒で高さを描いてから隣との差で面の向きに直し、光の当たる向きを面の中で変えます。

いちばん効いたのはでこぼこです。色を掛けるだけの絵は、離れて見るとほとんど変わりませんでした。面の中の明暗の幅を測っても増えていません。明るい所も暗い所も同じ割合で暗くなるため、かえって幅が狭まります。光の当たり方を変えるでこぼこの絵を足してから、板が金属らしく見えるようになりました。

絵は部品の大小に関係なく1枚ぶん貼られるので、そのままだと小さい部品ほど粒が細かくなります。部品の実寸を測り、だいたい1.2mで1枚になるように、部品ごとに貼り方の目盛りを引き伸ばしています。手で40箇所そろえてはいません。

盾の面だけは刃と同じ磨いた鋼にしました。見本でも盾は体より明るく見えます。

## 場面へなじませる

背景の中で浮いて見えたため、明るさと色を場面へ寄せました。見本の一枚絵を測ると、騎士の体は255段階で35〜60、すぐ後ろの背景は117〜133で、体のほうがずっと暗く沈んでいます。こちらも同じくらいになるまで光を落とし、鎧の青みを抜いて無彩色に近づけ、金と刃の明るさも下げました。上を向いた面へ空の白が映って光っていたので、映り込みに使う絵の上の面も暗くしています。

遠い面ほど空気の色を混ぜ、背中側と裾が背景へ溶けるようにしました。足元の丸い影にだけは混ぜません。混ぜると影が灰色に浮きます。

騎士の描画面は、背景の一枚絵より少し粗く描いてから画面の大きさへ広げ、さらに表示の設定でわずかににじませています。背景の絵は輪郭が柔らかいので、騎士の線だけくっきりしていると貼り付けたように見えます。粗く描くぶん、描く点は減ります。

- 18.5秒：魔法が届く時刻に合わせ、ひるむ姿勢と短い明るさの変化。
- 19.1秒ごろ：盾を寄せて構えを戻す。
- 20.8秒まで：待機姿勢へ戻る。
- 命中位置は、決め打ちの点ではなく、その時の胸の核の位置を画面上の座標へ直して使う。
- 背景だけが動いたり、元の騎士が二重に残ったりしないよう、騎士を除いた背景を使用。
- 命中の瞬間は胸の前の光源を強め、胸の核と兜の目を短く明るくし、体を短く震わせる。

見本の一枚絵と同じ見た目ではありません。鎧の細部は省き、輪郭と姿勢が分かることを優先しています。歩行、攻撃、倒れる動き、視点を回す表示は含みません。

## 効果音

ブラウザー内で短い音と雑音を合成します。外部の効果音ファイルは使っていません。

| 時刻 | 音 |
| --- | --- |
| 6秒・11秒 | 描き足しと詠唱の案内を示す小さい音 |
| 14.75秒 | 蓄積 |
| 16秒 | 完成 |
| 17秒 | 放出 |
| 18.5秒 | 命中。低い音と短い金属音。雷や氷では高い音も追加 |
| 22秒 | 終わりの小さい音 |

マイクを使う回は、録音と最後の文字を待つ14.75秒まで鳴らしません。最初の画面の「音を試す」で音量を確認できます。初期音量は25%。効果音のチェック、音量調整、プレイ中の「音を消す」で変更します。中止、画面を隠す、終了、再開では前の音を止めます。音が使えないブラウザーでもゲームは続けます。

音は開始操作後に用意します。録音用の接続とは別で、合成した音を音声認識へ直接渡す処理はありません。実際の会場のスピーカー音量は人が聞いて調整する必要があります。

## ファイル

- `src/render/knight.ts`：立体の騎士、3つの姿勢、視点、命中位置。
- `src/render/cast-scene.ts`：本編の時刻で騎士と術式を更新。
- `src/audio/cues.ts`：音を鳴らす時刻と録音中の扱い。
- `src/audio/cast-audio.ts`：音の生成、音量、停止、重複の防止。
- `src/knight-canvas.css`：騎士の描画面をにじませる設定。ゲーム画面、確認画面、演出の比較画面の3つから読み込みます。
- `src/look.ts`：確認画面。「待機」「被弾」「構えを戻す」で姿勢を止めて見られます。
- `public/art/ruins-empty-v1.png`：騎士を除いた背景。[生成時の指示](references/騎士と背景の分離_生成の指示.md)。
- 画像の騎士（`public/art/knight-poses-v1.png`）は立体のモデルに置き換えたため削除しました。必要ならGitの履歴から戻せます。

## 確認と残り

`npm test` は57件成功しました。命中前にひるまないこと、姿勢を戻すこと、音の時刻、録音中の無音、同じ音の重複を確認しました。ブラウザーでは実際の音の出力、消音、途中中止、音声認識と同時に使った発動を確認しました。画像は1440×900と390×844で見直しました。`npm run build` も成功しています。

初期音量25%で測った出力の最大振幅は約0.393で、測定した回では振幅の上限に達していません。消音と中止後の無音、終了時に音の生成処理が残っていないことも確認しました。再プレイの短い音を一度テストが取り逃がしたため、出力を20ms間隔で測り、その最大値を見る方法に直して再確認しました。

このPCのローカル認識とマウスを使った一回の測定では平均56.63fps、フレーム間隔の99パーセンタイル18.5ms、発動17.010秒でした。カメラは同時使用していません。音声は合成音声で、人の声や実際の会場での聞こえ方は未確認です。

立体の騎士へ置き換えた回は、開発用の環境で確認しました。`npm test` の57件と `npm run build` は成功し、開始画面、待機、被弾、構えを戻す、発動、結果までを1440×900と390×844で目視しています。命中位置が胸の核に付いてくることは、確認画面の照準を胸へ合わせて確かめました。

ただしこの環境の描画はソフトウェア処理で、毎秒1.6画面しか出ません。速度の数値は測り直していません。同じ環境で画像の騎士は毎秒1.7画面だったため、立体への置き換えで重くなった分はわずかです。GPUのあるPCでの `npm run test:browser` と、実機での速度の測り直しは残っています。画面が遅いと0.62秒しかないひるみの姿勢を飛ばすため、被弾の姿勢を見る確認はGPUのあるPCで行ってください。

形を作り込んだ回も、開発用の環境で確認しました。`npm test` の135件、`npm run build`、確認画面のブラウザー試験が成功し、待機・被弾・構えを戻すの3姿勢、開始画面、見本との並べ、1440×900と390×844を目視しています。開始画面で10秒間の画面数を数えたところ、作り込む前が毎秒3.62画面、作り込んだ後が毎秒3.51画面、元絵へ寄せた後が毎秒3.68画面、曲面にして面を増やした後が毎秒3.48画面、映り込みと影を足した後が毎秒3.44画面でした。ソフトウェア描画での比較で、実機の数値ではありません。

場面へなじませた回も同じ環境で確認しました。`npm test` の135件と `npm run build` が成功し、確認画面のブラウザー試験、3姿勢、開始画面、見本との並べ、1440×900と390×844を目視しています。見本と同じ場所の明るさを測り、兜47・肩56・胸57・腰47と、見本の56・53・50・45に近づいたことを数字でも確かめました。画面数は毎秒2.67画面です。にじませる処理を外すと毎秒3.66画面なので、下がった分はほぼこの処理です。ソフトウェア描画では画面全体の処理をCPUが行うため重く出ます。GPUのあるPCでは軽いはずですが未確認です。Macで遅ければ、にじみを外して粗く描くだけにすれば戻せます。

剣と盾を作り直した回と、表面の絵を貼った回も同じ環境で確認しました。`npm test` の135件と `npm run build`、確認画面のブラウザー試験が成功し、3姿勢と開始画面、見本との並べ、1440×900と390×844を目視しています。画面数は剣と盾の後が毎秒2.59画面、表面の絵の後が毎秒2.44画面です。でこぼこの絵は1つの点ごとに計算が増えるため、その分下がっています。ここもソフトウェア描画の数字で、GPUのあるPCでは軽いはずですが未確認です。

確認記録は `.local-speech/knight-audio-report.json`、実際のアプリ出力から作った試聴用の音は `.local-speech/knight-audio-preview.webm` に保存しています。後者は試聴ボタンと一回のプレイを含み、途中には無音があります。マイクの録音ではありません。どちらもGitには含めません。

今後も残るものは、床や鎧へ届く照明、攻撃・弱点・倒れる動き、音楽、60秒全体の防御と最後の魔法、実際の人の手と声による確認です。
