# 公開ページへ送る：ゲーム側の作業手順

みんなが作った魔法を一覧で見られる公開ページ（「みんなの魔導書」）を作ることになりました。公開ページそのものはVercelに別に作ります。この文書は、**ゲーム側（このリポジトリ）を直す手順**です。設計書 [とどめと結果](とどめと結果_詳細設計.md) の8章で「二段目」と呼んでいた部分にあたります。

この手順は、Codexなどの作業係にそのまま渡して動けるように書いてあります。上から順にやれば、途中で止めても壊れません。

## 0. 作業係への決まり

- まず `CLAUDE.md` と `README.md` を読む。文章、コメント、コミットメッセージは日本語で、既存のコードと同じ調子で書く。
- 変更のたびに `npm test` と `npm run build` を通す。ブラウザーの試験（`npm run test:browser`）はユーザーのMacで走らせるので、手順だけ残す。
- 回の表（`src/game/rounds.ts`）の時刻は変えない。送る時刻はすべてこの表から取る。
- 秘密の値（合言葉）は `.env` にだけ置く。`VITE_` を先頭に付けない。ブラウザーへ渡さない。
- 外部への送信で演出を延ばさない。返事を待たない。自動の再試行はしない。送れなかったときは「まだ届いていません」と出すだけにする。
- カメラの映像と声そのものは、今まで通り保存も送信もしない。
- 確認していないことを、確認したように文書に書かない。

## 1. 全体の形

```
会場のMacのブラウザー ──(1)──▶ 会場のMacの中のサーバー（server/index.ts） ──(2)──▶ Vercelの公開ページ
```

- (1) は今もある `/api/…` と同じ、自分のPCの中の通信。ブラウザーは公開ページと直接は話さない。
- (2) だけが外へ出る通信。合言葉（`BOOK_WRITE_KEY`）はサーバーが `.env` から読んで付ける。ブラウザーには渡さない。
- 公開ページの場所（`BOOK_URL`）が `.env` に無いときは、今まで通り「このPCの中だけ」の動きのままにする。**設定が無いときの見た目と動きを一切変えない**。今のブラウザー試験（`tests/browser/play.spec.ts` の76〜78行目）がそのまま通ることが目印。

送るのは「魔法が確定した」ときです。回の表の `lock` の時刻（一回目、防御、とどめの三回）で、今 `PlayRecorder.save` を呼んでいるのと同じ場所から送ります。とどめの回は `lock` が発動（`release`）より前なので、設計書の「最後の魔法は発動の演出中に送り、90秒を待たない」はこれで満たせます。途中でやめたときも、`saveCancelled` と同じ場所から一度だけ送ります。

## 2. 公開ページとの約束（先に固定する）

公開ページ側を作る人と食い違わないよう、ここに書いた形をそのまま使います。変えたいときは両方を同時に直します。

### 2.1 公開用の番号

- 遊びの開始時にブラウザーで `crypto.randomUUID()` を作り、`publicId` とする。推測しにくければよく、秘密ではない。
- 確認番号（6桁）とは別物。確認番号は今まで通り係員が読み上げる用で、公開ページには出さない。
- 「開始前に公開ページへ予約する」段取りは**やらない**。送るたびに同じ `publicId` で上書き保存（upsert）してもらうので、予約が無くても、届いた時点でQRの先が開く。届く前に開いたときは、公開ページ側が「まだ届いていません」と出す。

### 2.2 送る中身

2026年9月23日：ゲーム内の保存と確認用の記録には`flow`を追加済みです。下記の公開用の変換と送信はまだ未実装です。送るときは新しい値を引き継ぎ、名前が無い古い記録は`storedFlow(play)`で読みます。一回目の`voiceColors`があれば`sequential`、なければ`together`です。

`StoredPlay`（`src/game/record.ts`）をそのまま送らず、公開用の形 `PublicPlay` に写し取ってから送ります。生の点列（`rawPoints`。時刻付きの手のひらの位置）は公開ページに要らないので**送らない**。

```ts
/** 公開ページへ送る一回分。src/game/publish.ts に置く。 */
export type PublicPlay = {
  version: 'public-1';
  flow: 'sequential' | 'together'; // 遊び方。古い記録は storedFlow(play) で判定する
  publicId: string;          // 2.1 の番号
  startedAt: string;         // ISO 8601
  cancelled: boolean;
  completedRounds: number;
  viewport: { width: number; height: number }; // 絵の縦横比を戻すため
  rounds: Array<{
    round: 'first' | 'defend' | 'finish';
    title: string;           // ROUND_TITLES の値
    name: string | null;     // recipe.name。作れなかった回は null
    voiceColors?: string[]; // 声だけの回の円に残す色
    element: string | null;  // recipe.element
    purpose: string | null;  // recipe.purpose
    form: string | null;     // recipe.form
    count: number | null;    // recipe.count
    transcript: string;      // 詠唱の文字。無ければ空
    note: string;            // 結果画面の「ひとこと」と同じ文（record.ts の noteOf を export して使う）
    points: Array<{ x: number; y: number; stroke: number }>; // resultRows と同じ点列（防御は盾の形）。t と hand は落とす
  }>;
};
```

### 2.3 通信の形

| 向き | 方法と場所 | 中身 |
| --- | --- | --- |
| ブラウザー → Macのサーバー | `POST /api/book/plays` | JSONで `PublicPlay` 一件 |
| Macのサーバー → 公開ページ | `POST {BOOK_URL}/api/plays`、ヘッダー `Authorization: Bearer {BOOK_WRITE_KEY}` | 受け取った `PublicPlay` をそのまま転送 |
| 公開ページの返事 | `200` で `{ "ok": true }`。番号が変なら `400`。合言葉が違えば `401` | |
| ブラウザーが受け取る返事 | `{ "state": "delivered" \| "not-sent" \| "unconfigured" }` | `unconfigured` は `BOOK_URL` が無いとき |
| QRの先 | `{BOOK_URL}/s/{publicId}` | 一人ぶんのページ |
| みんなの一覧 | `{BOOK_URL}/book` | ゲーム側は使わない |

- サーバーから公開ページへの通信は、待つ時間の上限を8秒にする（`AbortSignal.timeout`）。超えたら `not-sent`。再試行しない。
- サーバーは `express.json` の上限が48KBなので、`/api/book/plays` だけ 512KB にする（表示用の点列が三回分入るため）。

## 4. 一つずつの中身

### 4.1 設定の入れ物

`.env.example` の最後に足す。

```
# みんなの魔導書（公開ページ）。空欄なら送らず、このPCの中だけに残す。
# 例: https://example.vercel.app  末尾に / を付けない
BOOK_URL=
# 公開ページへ書き込むための合言葉。公開ページ側の設定と同じ値にする。
BOOK_WRITE_KEY=
```

`server/index.ts` の `/api/status` の返事に `book: !!(process.env.BOOK_URL && process.env.BOOK_WRITE_KEY)` を足す。`README.md` の「設定（`.env`）」の表にも二行足す。

### 4.2 公開用の形を作る部品

新しいファイル `src/game/publish.ts`。ブラウザーとサーバーの両方から読めるよう、DOMに触らない純粋な関数だけにする。

- `export function publicPlayOf(play: StoredPlay, publicId: string): PublicPlay`
  - `rounds` は `resultRows(play)` を土台にする。点列は `resultRows` の `points` から `x, y, stroke` だけを写す（防御の回が盾の形になる決まりを、ここでもう一度書かない）。
  - `recipe` の `purpose`、`form`、`count` は `play.rounds[i].recipe` から取る。
  - `note` は `record.ts` の `noteOf` を `export` して使う。
- `export function validPublicPlay(value: unknown): value is PublicPlay`
  - サーバーが受け取ったものを確かめる。`version` が `public-1`、`publicId` がUUIDの形、`rounds` が3件以下、点が回ごとに 5000 個以下、文字列の長さの上限（`name` 80、`transcript` 400、`note` 200）。
- `export function bookPageUrl(baseUrl: string, publicId: string): string`
  - `{BOOK_URL}/s/{publicId}`。末尾の `/` の有無で二重にならないようにする。

試験は `tests/publish.test.ts` に新しく作る。`tests/record.test.ts` の `battleOf` と同じ作り方で戦いを作り、次を確かめる。

- `rawPoints` と `t`、`hand` が出力に無い。
- 三件の`name`と`element`が`resultRows`と同じ。
- `flow`が両方の遊び方で一致し、名前の無い古い記録も一回目の円の有無から正しく判定する。未知の値は受け付けない。
- 声だけの一回目は`voiceColors`と円で描ける。線が空でも絵を消さない。
- 防御の回の点列が盾の形（`guard.outline`）になっている。
- `validPublicPlay` が、正しいものを通し、`version` 違い、UUIDでない番号、点が多すぎるものを落とす。
- `bookPageUrl` が末尾 `/` の有無どちらでも同じURLを返す。

### 4.3 サーバーの転送口

新しいファイル `server/book.ts`。

```ts
export type BookSendResult = { state: 'delivered' | 'not-sent' | 'unconfigured'; reason?: string };
export async function sendToBook(play: PublicPlay, options: { url?: string; key?: string; fetcher?: typeof fetch; timeoutMs?: number }): Promise<BookSendResult>
```

- `url` か `key` が無ければ通信せず `unconfigured`。
- `POST {url}/api/plays`、`Content-Type: application/json`、`Authorization: Bearer {key}`。
- 上限は既定8秒。`AbortSignal.timeout` を使う。
- 返事が `200` なら `delivered`。それ以外と例外は `not-sent`。`reason` には状態番号か例外の文言を入れる（合言葉の値は絶対に入れない）。
- **再試行しない。** Jevの `evaluateJev` と同じ方針。

`server/index.ts` に足す。

```ts
app.post('/api/book/plays', express.json({ limit: '512kb' }), async (req, res) => {
  if (!validPublicPlay(req.body)) { res.status(400).json({ error: '入力の形式が正しくありません' }); return; }
  res.json(await sendToBook(req.body, { url: process.env.BOOK_URL, key: process.env.BOOK_WRITE_KEY }));
});
```

`app.use(express.json({limit:'48kb'}))` より前に置くか、この口だけ別の上限にする。どちらにしたかをコメントに書く。

試験は `tests/server.test.ts` に足す（偽の `fetcher` を渡す）。

- `url` が無いとき `fetcher` が呼ばれず `unconfigured`。
- 送ったURLが `{url}/api/plays`、ヘッダーに `Bearer` の合言葉、本文が渡した `PublicPlay` と同じ。
- `500` の返事で `not-sent` になり、`fetcher` は一回しか呼ばれない。
- 例外を投げる `fetcher` でも `not-sent` で、例外が外へ出ない。

### 4.4 ブラウザーからの送信

`src/main.ts` を直す。今の流れを壊さないよう、送る部分は `PlayRecorder` の横に足す。

1. `src/game/record.ts` の `PlayRecorder` に、公開ページへの送り先を足す。
   - `publicId: string`（`open` のときに `crypto.randomUUID()`。試験では引数で差し替えられるようにする）。
   - `bookState: 'unconfigured' | 'sending' | 'delivered' | 'not-sent'`（初期は `unconfigured`）。
   - `sender: ((play: PublicPlay) => Promise<BookSendResult>) | null`。`main.ts` から `fetch('/api/book/plays', …)` を包んだ関数を渡す。試験では偽の関数を渡す。
   - `save` と `saveCancelled` の中で、このPCへの保存が終わったあと、`sender` があれば `publicPlayOf(play, this.publicId)` を送る。返事を待たずに `bookState` を `sending` にし、返事が来たら `delivered` か `not-sent` に変える。`unconfigured` が返ったら `unconfigured` のまま。
   - 送信の途中で次の確定が来たら、古い送信の返事で新しい状態を上書きしない（送った順番を番号で持ち、最後に送ったものの返事だけを採る）。
   - `delivery` の決め方を次のようにする。
     - `bookState` が `delivered` → `delivered`
     - `sending` → `sending`
     - `not-sent` → `not-sent`
     - `unconfigured` → 今まで通り（`local-only` か `not-stored`）
   - `DELIVERY_MESSAGES` の文言は今のまま使う。
2. `main.ts` の `PlayRecorder.open(...)` の直後で、`status.book` が真のときだけ `sender` を渡す。偽のときは渡さない（設定が無いときは通信ゼロ）。
3. `report()`（確認用の記録）に `publicId` と `bookState` を足す。合言葉は入れない。
4. `diag.log` に「公開ページへ送信」「公開ページの返事」を足し、`docs/確認用の記録の見方.md` にも一行足す。

演出に関わる時刻、`driveRound`、音、描画は触らない。

### 4.5 魔導書のQRと一行

- QRの絵を作る部品として `qrcode` パッケージ（npm、MITライセンス）を `dependencies` に足す。`import QRCode from 'qrcode'` で `QRCode.toCanvas(canvas, url, { margin: 1, width: … })` を使う。他の候補で迷わない。
- `src/main.ts` の魔導書の組み立て（`el('confirm-number')…` のあたり）で、`recorder.delivery` を見て切り替える。
  - `delivered` か `sending`：`#qr-slot` の中身を `canvas` に置き換えてQRを描く。QRの中身は `bookPageUrl(status.bookUrl, recorder.publicId)`。そのために `/api/status` の返事に `bookUrl`（`BOOK_URL` の値。秘密ではない）も足す。
  - `not-sent`：`#qr-slot` の文字を「まだ届いていません」にする。QRは出さない。
  - `unconfigured`（`local-only` / `not-stored`）：今まで通り「持ち帰りの準備中」。
- 90秒の時点で `sending` のままなら、返事が来たときに `#qr-slot` と `#save-state` を描き直す（結果画面が出ている間だけ）。
- 縦長の画面でも三件の帯がQRに隠れないことを、`node scripts/capture-90s.mjs` の写真で見る（設定が無い状態と、`.env` に仮の値を入れた状態の二通り）。仮の値のときはサーバーが `not-sent` を返すので、「まだ届いていません」の見た目が確かめられる。

## 6. Macで確かめてもらう手順（ユーザー向け）

1. `.env` に `BOOK_URL` と `BOOK_WRITE_KEY` を入れる（公開ページ側と同じ値）。
2. `npm run dev` で起動し、一回遊ぶ。
3. 90秒の魔導書にQRが出て、下の一行が「持ち帰れます」になっているか見る。
4. スマホでQRを読み、自分の3つの魔法が出るか見る。
5. `{BOOK_URL}/book` を開き、今の一件が一覧の先頭に出るか見る。
6. `?dev=1` の「記録を保存する」で落ちるJSONの `bookState` が `delivered` になっているか見る。

## 7. 決まったこと

| 決めたこと | 中身 |
| --- | --- |
| 通信の経路 | ブラウザーは公開ページと直接話さず、Macの中のサーバーが合言葉を付けて転送する |
| 開始前の予約 | やらない。送るたびに同じ番号で上書き保存してもらう |
| 送る中身 | 表示用の点列、魔法名、属性、用途、形、数、詠唱の文字、ひとこと。生の点列と確認番号は送らない |

| 設定が無いとき | 通信をせず、見た目も動きも今のまま |
