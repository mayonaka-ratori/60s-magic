# 画面の整理案（重なり・余分な文字・余分なUI）

遊ぶ人の目から見て、読めない文字、要らない文字、要らないボタンを洗い出しました。
実際にアプリを動かし、1920×1080／1440×900／1280×800／1024×768／390×844の5つの大きさで、
開始前、描いている間、完成、発動、結果、説明の小窓まで画面を撮って位置を測っています。

数字はすべて実測です（`npm run dev`で起動し、Chromiumで撮影）。

---

## 1. 文字が重なっている箇所

### 1-1. 残り時間と「中止する」「音を消す」（全部の大きさで発生）

プレイ中、右上の時間表示の下半分に「中止する」のボタンがかぶっています。

| 大きさ | 時間表示 | 中止するボタン | 重なり |
| --- | --- | --- | --- |
| 1440×900 | x1267〜1398 / y66〜110 | x1342〜1404 / y95〜124 | 横56px×縦15px |
| 1280×800 | x1107〜1238 / y66〜110 | x1182〜1244 / y95〜124 | 横56px×縦15px |
| 1024×768 | x851〜982 / y66〜110 | x926〜988 / y95〜124 | 横56px×縦15px |

「03 / 24秒」の「/ 24秒」がボタンの下に隠れて読めません。24秒しかない遊びで、
残りがあと何秒かが一番隠れてはいけない文字です。
390×844では時間とボタンは離れますが、代わりに「中止する」が敵の名前「遺跡の騎士」に
横8px×縦6pxかぶります。

場所：`src/main.ts:16`（時間表示）、`src/main.ts:26`（中止するボタン）、
`src/style.css`の`.exit{top:105px}`、`src/cast-style.css`の`.exit{top:95px}`と`.sound-toggle{top:136px}`

### 1-2. 開始前の画面。「第一幕 / 最初の魔法」と「描いて、唱えて、解き放つ。」

ブラウザーの表示領域の高さが約840pxより低いと、真ん中の文章が上へ伸びて、
左上のキャッチコピーと重なります。1280×800と1024×768で発生しました。
1024×768では二つの文字が完全に混ざって、どちらも読めません。

高さ900pxでは起きません。つまり1080pのモニターでも、ブラウザーのタブやブックマーク欄の
分だけ表示領域が縮むと出ます。普通のノートPCではほぼ必ず出る重なりです。

場所：`src/main.ts:16`（`.eyebrow`）、`src/main.ts:17`（`.chapter`）、
`src/cast-style.css`の`.welcome{transform:translateY(-47%)}`

### 1-3. 開始前の画面。説明文とフッター

同じ高さのとき、下の「カメラの映像はこのPC内で処理します…」と、
一番下の「形に正解はありません。小さな動きでも大丈夫。」が縦に9〜11px重なります。

場所：`src/main.ts:23`（`.privacy`）、`src/main.ts:25`（`.ready-footer`）

### 1-4. 「見本の再生」と敵の名前

見本を再生すると、上中央の「見本の再生」の札が、体力バーの「遺跡の騎士」に
縦12pxほどかぶります（1440×900で確認）。札が上、名前が下で、名前が読めません。

場所：`src/main.ts:26`、`src/style.css`の`.demo-tag{top:36px}`と`.enemy-health{top:110px}`、
`src/cast-style.css`の`.enemy-health{top:6%}`

### 1-5. 余裕が4pxしかない場所

1440×900と1280×800で、左下の「声の代わりに文字で試せます」と、
下中央の案内枠の間が4pxしかありません。文字が1行増えると重なります。
通信の不具合を知らせる文章（`src/main.ts:142`）はこの同じ場所に出るので、
長い文章が来ると案内枠にぶつかります。

## 2. 遊ぶ人には要らない文字とUI

作った人のための文字が、遊ぶ人の画面にそのまま出ています。

| 場所 | いまの文字 | なぜ要らないか |
| --- | --- | --- |
| 右上（最初から最後まで） | 最初の24秒・試作 | 開発の段階の話。遊んでいる間ずっと出ている |
| 開始前の右側 | 向こうにいるのは、一体の騎士 | 体力バーに「遺跡の騎士」と出るので二度言っている |
| 開始前の右下 | 描く14秒 → 完成3秒 → 発動と余韻 | 中の作りの時間割。遊ぶ人は秒数を管理しない |
| 開始前のボタン | 接続の確認 | 中身はJev、npmの命令、README。遊ぶ人には読めない |
| 開始前のリンク | 新しい背景・騎士・術式を見る ↗ | 開発の確認画面（`/?view=look`）へのリンク |
| 開始前の説明文 | Jevは未接続です | Jevが何かを知らない人には不安なだけ |
| マイクの項目 | （接続の確認をご覧ください） | 使えない理由の案内が、開発者向けの画面へ誘導している |
| 準備中の知らせ | 準備しています。許可と読み込みの時間は24秒に含みません。 | 24秒に含む含まないは中の話 |
| カメラ未準備の知らせ | 手の認識ファイルがありません。接続の確認から準備方法をご覧ください。 | 遊ぶ人にはどうにもできない |
| 最後の案内 | 今回の試作は、ここまでです | 遊びの余韻が切れる |
| 結果 | 一回目の魔法が完成しました | 「一回目」は開発の数え方 |
| 結果 | 確認用の記録を見る／記録を保存する | JSONの書き出し。検証のための道具 |
| 結果 | 自分の魔法を放ったと感じましたか？ | 作り手のための聞き取り |
| 詠唱の言葉の小窓 | 作品の用語は読み方の参考です。その作品の技を再現する機能はありません。 | 権利まわりの注意書き |

### まとめ方の案

これらを一つずつ消すより、`?dev=1`のときだけ出る「確認用の表示」としてまとめるのが早いです。

- ふだん（遊ぶ人）：試作の札、接続の確認、見た目の確認へのリンク、記録の書き出し、聞き取りを出さない
- `?dev=1`（作る人と展示の担当）：今までどおり全部出す

`src/entry.ts`がすでに`?view=look`で画面を分けているので、同じやり方で足せます。

## 3. 同じことを二度言っている文字

1. **文字入力の案内が二つ**
   左下に「声の代わりに文字で試せます」、右側の入力欄の見出しに「声の代わりに、文字で試す」。
   同じ画面に同じ意味が二つ出ます（`src/main.ts:27`と`src/main.ts:28`）。
   入力欄の見出しだけ残せば足ります。

2. **入力が終わったのに残る案内**
   左下の「声の代わりに文字で試せます」は、結果が出る24秒まで消えません。
   文字を入れられるのは14秒までなので、発動中に「文字で試せます」と出ているのは間違いです
   （`src/main.ts:104`、消えるのは`finish()`の`src/main.ts:155`）。
   入力欄と同じく14秒で消すべきです。

3. **敵の名前が二つ**
   開始前の「向こうにいるのは、一体の騎士」と、プレイ中の体力バーの「遺跡の騎士」。

4. **通信の知らせが案内の場所を乗っ取る**
   `src/main.ts:142`で、通信の不具合の文章を「声の代わりに…」と同じ場所へ上書きしています。
   知らせが出ると入力の案内が消えるので、別の場所に分けたほうがよいです。

## 4. 読みにくい文字

- 10px以下の文字が多すぎます。プレイ中だけでも、`.phase-caption`10px、`.steps`10px、
  `.hint`11px、`.exit`10px、`.sound-toggle`10px。390pxの画面では9pxまで下がります。
  離れて見る展示では読めません。11〜13pxを下限にしたいところです。
- 下中央の枠に「手の動きを、光に」「押したまま、自由に描こう」「画面を押したまま、少し動かそう」
  「1描く・唱える／2術式完成／3発動」の4段が同時に出ます。
  1行目と2行目と3行目がほぼ同じことを言っているので、2段で足ります。
- 「術式」「発動」は雰囲気の言葉としては良いのですが、進み具合を示す番号付きの並びでは
  「線を描く」「形になる」「放つ」のほうが一目で分かります。
- 結果の「無属性 / 攻撃 / 光線」は記号の並びで、説明書のように見えます。
- 時間表示は経過秒（`03 / 24秒`）です。残り秒のほうが急ぐ気持ちが伝わります。
- 効果音の列に「効果音」「音量」つまみ「25%」「音を試す」の4つが11px以下で並びます。
  最初の画面では入／切だけで足ります。

## 5. 画面ごとの変更案

### 開始前

- 上の重なりを止める。表示領域の高さが低いときは真ん中揃えをやめ、ヘッダーの下から順に置く。

```css
@media(max-height:880px){
  .welcome{top:96px;transform:none;max-height:calc(100dvh - 150px);overflow:auto}
  .ready-footer{display:none}
}
```

- 「形に正解はありません。小さな動きでも大丈夫。」は遊ぶ人に効く言葉なので、
  フッターから本文側（「魔法をつくる」の下）へ移す。
- 「描く14秒 → 完成3秒 → 発動と余韻」は消すか、「1回は24秒です」に置き換える。
- 「向こうにいるのは、一体の騎士」は消す。
- 説明文は1行に縮める。
  今：カメラの映像はこのPC内で処理します。音声もこのPC内で文字に変え、外へ送りません。Jevは未接続です。この試作では自動保存しません。
  案：カメラも声もこのPCの中だけで扱い、外へ送りません。保存もしません。
- マイクが使えないときの言葉。
  今：マイクで唱える （接続の確認をご覧ください）
  案：マイクで唱える（このPCではいまマイクを使えません）
- カメラを準備できていないときの知らせ。
  今：手の認識ファイルがありません。接続の確認から準備方法をご覧ください。
  案：いまは手で描けません。「マウスで試す」で遊べます。
- 効果音は入／切だけ表に出し、音量と「音を試す」はたたむ。
- 「接続の確認」と「新しい背景・騎士・術式を見る ↗」は`?dev=1`のときだけ出す。

### プレイ中

- 右上を1列に整える。上から、残り時間、中止する、音を消す。重ならない位置に置く。

```css
.exit{top:118px}
.sound-toggle{top:156px}
#app[data-screen=playing] .trial{display:none}
```

  「最初の24秒・試作」を消すと、そのぶん全体を上へ寄せられます。
- 時間表示は残り秒にする。「あと12秒」のように。
- 「見本の再生」の札は上中央をやめ、左上（ロゴの下）へ移す。
- 左下の「声の代わりに文字で試せます」は消し、案内は入力欄の見出しに一本化する。
  マイクを使う回だけ「声を受け付けています」を残す。
- 通信の知らせは、案内の場所を上書きせず、中止するボタンの下に出す。
- 下の枠は2段にする。

| いま | 案 |
| --- | --- |
| 手の動きを、光に／押したまま、自由に描こう／画面を押したまま、少し動かそう | 押したまま、自由に描こう／止まっても、描き足せます |
| 描いた線に、光が集まる／そのまま、描き足して／好きな言葉を、いつ唱え始めても大丈夫 | そのまま描き足して／好きな言葉を唱えても大丈夫 |

- 進み具合の並びは「線を描く」「形になる」「放つ」にする。

### 結果

- 「一回目の魔法が完成しました」→「あなたの魔法ができました」
- 「無属性 / 攻撃 / 光線」→「無属性の攻撃。光線のかたち。」
- 「確認用の記録を見る」「記録を保存する」「自分の魔法を放ったと感じましたか？」は
  `?dev=1`のときだけ出す。遊ぶ人には「もう一度つくる」「最初へ戻る」の2つだけ見せる。
- 「今回の試作は、ここまでです」→「ここまでが、はじまりの一撃」など余韻の残る言葉にする。

### 説明の小窓

- 「詠唱の言葉」は80語ほどの一覧を一度に出しています。遊ぶ直前に読む量ではありません。
  例を3つと、属性ごとの代表語を2〜3語だけにして、残りはたたむ。
- 小窓の「閉じる」が一覧の下にあり、画面外へ出ています。閉じるボタンは上に置くか、
  背景を押しても閉じるようにする。いまはEscでも閉じられますが、画面に書かれていません。
- 末尾の「作品の用語は読み方の参考です。…」は出さない。

## 6. 直す順番

1. 右上の重なり（残り時間が読めない。全ての大きさで起きる）
2. 開始前の上下の重なり（高さ840px未満で起きる。ノートPCでほぼ必ず出る）
3. 入力の案内の重複と、14秒を過ぎても残る案内
4. `?dev=1`で開発用の文字とボタンを分ける
5. 「見本の再生」の札の位置
6. 文字の大きさと言い回しの見直し

1から3までで、遊ぶ人が引っかかる場所はほぼ無くなります。

## 7. 確認のしかた

`tests/browser/cast-layout.spec.ts`と同じやり方で、重なりを機械的に確かめられます。
主な文字の四角形を集めて、親子でない組み合わせが重なっていないかを見ます。
1440×900、1280×800、1024×768、390×844の4つで通れば、今回見つけた重なりは戻ってきません。
