# 背景・騎士・完成した術式の確認

2026年9月20日。指定された8画面のうち、3画面目の完成した術式を基準に実装しました。

## 開く

起動中のアプリで `http://localhost:5173/?view=look` を開きます。本編の開始画面にもリンクがあります。

- 「見本と並べる」で右側に指定画像の3画面目を表示します。狭い画面では横に送って比較できます。
- 「待機」「被弾」「構えを戻す」で騎士の姿勢を止めて見られます。被弾は18.7秒、構えを戻す途中は19.9秒の姿勢で止めています（本編では19.1秒から戻り始め、19.3〜20.2秒がその姿勢です）。
- 「自分の線で試す」で画面を押したまま描き、「完成形を見る」で形を保って縮小・配置します。
- 「見本の線に戻す」で最初の例へ戻ります。
- 「光の強さ」で光点と周囲の青い光を調整します。
- カメラ、マイク、Jevはこの確認画面では起動しません。

## 実装したもの

背景は内蔵の画像生成機能で生成した、一枚の静止画です。最初に作った騎士入りの画像は `public/art/ruins-knight-v1.png`、騎士を除いた背景は `public/art/ruins-empty-v1.png` に保存しています。生成に使った指示は [画像生成の指示](references/背景と騎士_生成の指示.md) に保存しました。

騎士は画像ではなく、アプリ内で組み立てた立体のモデルです。この画面でも本編と同じモデルと視点を使い、3つの姿勢を止めて見られます。[騎士の動きと効果音](騎士の動きと効果音.md)。画面中央の照準は決め打ちの位置ではなく、その時の胸の核の位置に合わせています。

術式は背景の画像に含めず、Babylon.jsで入力点から線、少数の光点、中心の輪、補助線、外周の目盛りを描きます。光点の青い光もアプリで描画しています。Three.jsの追加は行っていません。

線の端と大きな折れ目を優先して光点を置きます。完成時の大きさは縦横比を保って調整し、元の入力点と筆の切れ目を残します。自分で描き直すと、最初の例の線は使いません。確認画面は最大1024点で、本編の記録には影響しません。

新しい表示は `src/look.ts`、術式の描画は `src/render/completed-spell.ts`、形を保つ配置は `src/render/spell-layout.ts` です。本編と確認画面の入口を `src/entry.ts` で分けています。

## 本編への接続

`http://localhost:5173/` で、新しい背景と術式を使った24秒を遊べます。`src/render/cast-scene.ts` が同じ時刻で入力、完成、放出を進めます。

- 0〜14秒：本人が描く位置に線を表示。6秒以降は光が線の上をたどる。声の大きさも光へ反映。
- 14〜17秒：縦横比と筆の切れ目を保ち、線を足元の完成位置へ滑らかに収める。入力の記録は変更しない。
- 17秒：魔法の種類・個数に応じて術式から放出。奥へ小さくなる輪で進む向きを見せる。
- 18.5秒：騎士の胸へ到達し、光と火花を表示。命中位置はその時の胸の核の位置から求める。
- 21〜23秒：術式と放出後の光を消す。
- 24秒：背景をぼかし、結果の枠内に本人の線を表示。小さくしても元の画面の縦横比を保つ。

入力が変わったときだけ線の形を更新し、完成後は毎フレーム線を作り直さず、位置・大きさ・光だけを変えます。騎士は立体のモデルで、命中時にひるんだ姿勢から構えを戻します。歩行、攻撃、倒れる動きは含みません。

## 見本と比較した結果

- 曇り空、石の床と柱、奥の城、剣と盾を持つ騎士をそろえました。騎士は輪郭と姿勢が分かる簡単な立体で、鎧の細部は省いています。
- 初回の確認で青い光が弱かったため、光点の周囲に青い光を加え、主線の色と幅を調整しました。
- 画面全体に線が広がる状態を避け、足元から手前に完成した形を置きました。
- 日本語にはNoto Sans JPとNoto Serif JPを使い、ブラウザー画像で表示を確認しました。

完全な一致ではありません。騎士の比率・装飾は見本と異なります。魔法の光は画面上で重ねており、立体の鎧や床へ実際に照明が当たる処理にはなっていません。

## この時点で残るもの

1. 鎧や床へ光が届く照明を追加する。
2. 攻撃、弱点が現れる姿勢、倒れる動きを追加する。
3. 実際の人の手と声を同時に使い、24秒全体の認識精度と体感を確認する。

背景・完成した術式の確認に続き、蓄積と発動を本編へ接続しました。60秒への拡張はまだ行っていません。

## 確認

- `npm run build` 成功。
- `npm test` 53件成功。大きな入力の収まり、元の点と筆の切れ目の保持、14秒以前の位置、17秒の完成位置、画像上の命中位置を含みます。
- `npx playwright test tests/browser/look.spec.ts` 成功。読み込み、比較、二筆の描き直し、完成、復元、390×844の表示を確認。
- 既存の24秒を最後まで遊ぶブラウザーテストも成功。今回の入口の変更後も、七つの雷、結果、入力の記録を確認。
- 新しい本編で、Jevの遅延・期限内回答、カメラの起動と中止、見本の中止、大きい二筆の入力、390×844の結果と再プレイ、ローカル音声認識との同時動作を確認。
- ローカル音声認識とマウスを使った一回の自動確認では平均59.75fps、99%のフレームが16.9ms以内、発動は17.009秒。これはこのPCで合成音声を使った結果で、人の手と声を同時に使った測定ではありません。
- 実際の画面を `test-results/look-complete.png`、`look-compare.png`、`look-own-lines.png`、`look-mobile.png` へ保存して目視確認。
- 騎士を立体のモデルへ置き換えた後、`npm test` 57件と `npm run build` が成功。確認画面で待機・被弾・構えを戻すの3姿勢、見本との並べ表示、390×844で横にはみ出さないこと、照準が胸に付いてくることを目視しました。この確認はソフトウェア描画の環境で行ったため、速度の数値は含みません。
