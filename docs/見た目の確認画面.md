# 背景・騎士・完成した術式の確認

2026年9月20日に、指定された8画面のうち3画面目の完成した術式を基準に作った確認画面と、その見た目を本編へつないだ部分の説明です。

## 開く

起動中のアプリで `http://localhost:5173/?view=look` を開きます。開発用の表示（`http://localhost:5173/?dev=1`）の開始画面にある「新しい背景・騎士・術式を見る」からも開けます。

- 「見本と並べる」で右側に指定画像の3画面目を表示します。狭い画面では横に送って比べられます。
- 「待機」「被弾」「構えを戻す」で騎士の姿勢を止めて見られます。被弾は一回目の命中の0.2秒後、構えを戻す途中は命中の1.4秒後の姿勢です。何も付けずに開くと「順番に」の表で19.7秒と20.9秒、`&flow=together` を付けると「同時に」の表で23.7秒と24.9秒になります。止める姿勢そのものは同じです。
- 「待機」だけは止めずに動かします。剣を振りかぶった構えで、5.6秒に一度ゆっくり剣が上下します。
- 体力の帯は本編と同じ見せ方（画面の右端に縦、名前は縦書き）にそろえた飾りで、減りません。
- 「自分の線で試す」で画面を押したまま描き、「完成形を見る」で本編と同じ決まりで置きます。描いた場所と大きさのまま残し、小さければ広げ、画面の端や上下の帯にかかれば中へ寄せます。
- 「見本の線に戻す」で最初の例へ戻ります。
- 「光の強さ」で光点と周囲の青い光を調整します。
- カメラ、マイク、Jevはこの確認画面では起動しません。

## 作ったもの

背景は内蔵の画像生成機能で作った一枚の静止画です。最初に作った騎士入りの画像は `public/art/ruins-knight-v1.png`、騎士を除いた背景は `public/art/ruins-empty-v1.png` にあります。生成に使った指示は [画像生成の指示](references/背景と騎士_生成の指示.md) に保存しています。購入した外部素材は使っていません。比較用の指定画像は `public/art/visual-reference.png` に複製しています。

騎士は画像ではなく、アプリ内で組み立てた立体のモデルです。この画面でも本編と同じモデルと視点を使います（[騎士の動きと効果音](騎士の動きと効果音.md)）。画面中央の照準は決め打ちの位置ではなく、その時の胸の核の位置に合わせています。

術式は背景の画像に含めず、Babylon.jsで入力点から線、少数の光点、中心の輪、補助線、外周の目盛りを描きます。光点の青い光もアプリで描いています。Three.jsは使っていません。

線の端と大きな折れ目を優先して光点を置きます。元の入力点と筆の切れ目は残します。自分で描き直すと、最初の例の線は使いません。確認画面で描ける点は最大1024点で、本編の記録には影響しません。

確認画面は `src/look.ts`、術式の描画は `src/render/completed-spell.ts`、術式を置く場所の決まりは `src/render/spell-layout.ts` です。本編、確認画面、演出の見比べ画面の入口は `src/entry.ts` で分けています。

## 本編への接続

`http://localhost:5173/` で、この背景と術式を使った90秒（一回目、防御、とどめ）を遊べます。`src/render/cast-scene.ts` が同じ時刻で入力、完成、放出を進めます。

線で術式を描く回の流れは次のとおりです。時刻は「同時に」の一回目のものです。

- 0〜18秒：本人が描く位置に線を表示。7秒以降は光が線の上をたどる。声の大きさも光へ反映。
- 18〜22秒：縦横比と筆の切れ目を保ったまま、置く場所へ滑らかに移す。描いた場所と大きさのままなら動かない。入力の記録は変えない。
- 22秒：魔法の種類と個数に応じて術式から放出。
- 23.5秒：騎士の胸へ届き、光と火花を表示。命中位置はその時の胸の核の位置から求める。
- 26秒から術式と放出後の光が薄れ、28秒で消える。
- 90秒：背景をぼかし、結果の枠内に本人の線を表示。小さくしても元の画面の縦横比を保つ。

「順番に」では、一回目は声だけで線を描かないので、線の術式は防御の回（26〜38秒に描く）から出ます。防御ととどめの回は描き始めから光が線をたどり、声の大きさは光へ反映しません。とどめの回は62秒で描くのを締め切り、そこから発動の76秒までかけて置く場所へ移ります。

入力が変わったときだけ線の形を作り直し、完成後は位置、大きさ、光だけを変えます。術式を置く決まりの細かい数値は[画面全体を使う演出と、敵の圧](画面全体と敵の圧_実装.md)にあります。

## 見本と比べた結果

- 曇り空、石の床と柱、奥の城、剣と盾を持つ騎士をそろえました。騎士は輪郭と姿勢が分かる立体で、鎧の細部は省いています。
- 初回の確認で青い光が弱かったため、光点の周囲に青い光を加え、主線の色と幅を合わせました。
- 日本語にはNoto Sans JPとNoto Serif JPを使い、ブラウザーの画面写真で表示を確認しました。

完全な一致ではありません。騎士の比率と装飾は見本と異なります。魔法の光は画面の上に重ねて描いていて、立体の鎧や床へ照明が当たる処理にはなっていません。

## 試験

`tests/browser/look.spec.ts` が、「同時に」の表（`?view=look&flow=together`）で、読み込み、3つの姿勢の切り替え、見本との並べ表示、二筆の描き直しと完成、見本の線への復元、390×844で横にはみ出さないことを見ます。画面写真を `test-results/` の `look-complete.png`、`look-knight-hit.png`、`look-compare.png`、`look-own-lines.png`、`look-mobile.png` に保存するので、目で見て確かめられます。

## 確認の記録

作ったときの記録です。そのときは60秒の流れで、試験の件数もそのときのものです。今の件数は[実装と確認の記録](実装と確認の記録.md)にあります。

- 2026年9月20日、そのときの `npm test`（53件）、`npm run build`、`look.spec.ts` が通りました。本編でも、Jevの遅延と期限内の回答、カメラの起動と中止、見本の中止、大きい二筆の入力、390×844の結果と再プレイ、ローカル音声認識との同時動作を確かめました。
- 騎士を立体のモデルへ置き換えた後、確認画面で3姿勢、見本との並べ表示、390×844で横にはみ出さないこと、照準が胸に付いてくることを目で確かめました。ソフトウェア描画の環境だったので、速さの数値はありません。

## 残っていること

- 鎧や床へ魔法の光が届く照明。
- 実際の人の手と声で、90秒全体の認識の精度と遊んだ感じを確かめること。
