# とどめと結果：詳細設計

2026年9月20日作成、9月21日に90秒へ直しました。とどめの回と、90秒からの結果画面（魔導書）を作るための設計です。**この設計にそって作ってあります。** どこまで作ったかは14章、実装で設計から変えたところは各章の「実装では」にあります。レビューで決まったことは15章です。

**二つの遊び方との関係。** この文書を書いたときは「描きながら唱える」遊び方（今の「同時に」）しかなかったので、入力の時刻は「同時に」の表で書いています。標準の「順番に」では、とどめの回は50秒に始まり、62秒まで描いて、そのあと72秒まで唱えます（[順番に入力する遊び方](順番に入力する遊び方_設計.md)の5章）。**締め切り（72秒）から後ろの時刻、つまり確定、発動、命中、崩れ落ち、余韻、魔導書は、二つの遊び方で同じです。** この文書の72秒より後ろの話は、どちらの遊び方にもそのまま当てはまります。

## 0. この回でやりたいこと

**「自分が作った一番大きい魔法で、目の前の騎士を倒した」を、主観視点のまま見せきる。** 三回目なので、同じ手を大きくしただけでは弱く見えます。とどめだけに使う段取りを別に用意します。難しさは作らず、入力がどうであれ必ず倒れます。

作る範囲は次の四つです。

1. とどめの回（「同時に」は56〜90秒、「順番に」は50〜90秒）の進行と演出
2. 騎士が崩れ落ちる動きと、体力が必ず0になること
3. 結果画面（魔導書）の見た目と、三つの魔法の並べ方
4. 持ち帰りの下ごしらえ（このPCの中への保存と確認番号まで。公開ページと本物のQRは、ほかが全部できた後）

## 2. 世界の時計に「遅くする」を足す

作る前の世界の時計は「命中で止める」だけを持っていました。とどめでは、止めるのが2回あり、さらにスローモーションが入ります。時計の計算をひとつにまとめ直しました（`src/render/effects/screen.ts` の `warpOf` と `warpTime`）。

### 二つの時計

この回からは、時計が二つあることをはっきり分けて書きます。

- **実際の時刻**：開始からの本当の経過。画面の残り時間、魔導書を出す90.0秒、録音の締め切りはこちら。
- **世界の時刻**：止めとスローを入れたあとの時刻。騎士、術式、魔法、粒、体力はこちらで動きます。

止めもスローも**世界の時刻で置きます**。長さは実際の秒数で指定します。こうすると、描く側（世界の時刻）と、置いた時刻がぴたりと合います。

### 形

```
ゆがみ = {
  stops: [{ at: 世界の時刻, hold: 実際に止める秒数 }, ...],   // 時刻の順に並べる
  slow:  { from: 世界の時刻, seconds: 実際の長さ, rate: 速さの倍率 } | null
}

世界の時刻(t) を出す手順：
  遅れ = 0
  出来事を順に見る：
    その出来事が始まる実際の時刻 = at + 遅れ
    t がそこへ届いていなければ、そこで終わり
    止めなら   遅れ += min(hold, t - 始まる実際の時刻)
    スローなら 遅れ += (1 - rate) × min(seconds, t - 始まる実際の時刻)
  返す値 = t - 遅れ
```

- 止めている間は、遅れが t と同じ速さで増えるので、世界の時刻はぴたりと止まります。
- スローの間は、世界の時刻が rate 倍の速さで進みます。
- 時刻だけで決まる計算なので、今までどおり試験できます。時計が戻ることはありません。
- **ゆがみの中身は、本人の魔法（弾の数や属性）で変えません。** 止める時刻と長さは回の表から決めます。こうすると遅れの合計がいつも同じになり、余韻の長さも試験で固定できます。

### 一回目と防御のゆがみ

設計では、一回目と防御は `stops` が一つ（命中の時刻に、それまでと同じ長さ）、`slow` は `null` にして、作り直す前の `effectTime` とまったく同じ値になることを総当たりの試験で確かめてから進める、としていました。

実装はその後の演出の更新で変わっています。防御は命中で一回だけ止めます（0.14秒）。一回目は命中で止めたあと、0.08秒後と0.2秒後にもう一度ずつ短く止め直す三段です（`HIT_STAGES`）。控えめモードでは、一回目と防御は止めません。

### とどめのゆがみと、二つの時計のずれ

止めるのは、一発目の命中と、とどめの一撃の2回だけです。仕様の1.7にある「命中時に約0.1秒止める」を一発目で守り、とどめの一撃だけ0.25秒まで伸ばします。間の小さい命中では止めません（揺れと光だけ）。

| 世界の時刻 | 何を | 長さ（実際） | 実際の時刻 | ここまでの遅れ |
| --- | --- | --- | --- | --- |
| 77.60 | 一発目の命中で止める | 0.10秒 | 77.60〜77.70 | 0.10秒 |
| 78.50 | とどめの一撃で止める | 0.25秒 | 78.60〜78.85 | 0.35秒 |
| 78.80 | 0.25倍のスロー | 0.50秒 | 79.15〜79.65 | 0.725秒 |

合計の遅れは0.725秒です。つまり**実際の90.0秒のとき、世界の時刻は89.275秒**です。控えめモードは止めないので、同じ実際の90.0秒で世界は89.625秒です。崩れ落ちは世界の時刻で82.00秒までに終わらせ、そのあとの余韻は世界の90.00秒まで続けます。実際の90.0秒では世界の時計がまだ手前なので、術式の光がわずかに残ったまま結果画面へ渡ります。

止める回数を増やすほど遅れが増え、余韻が削られます。**止めるのは3回まで、遅れの合計は0.8秒まで**と決めておきます（`WARP_LIMITS`）。試験でこれを超えたら止めます。

## 4. とどめだけの見せ方（作る部品）

`src/render/effects/finish.ts` に次の五つを入れてあります。ほかの回からは呼びません。

### 4.1 術式が視界を通り抜ける（76.00〜76.25秒）

完成した術式の形（本人が描いた線）を、中心から外へ一気に広げます。広がりきる手前で線が薄くなり、画面の外へ抜けます。

- 拡大の倍率は画面の大きさから決めます（初めの案の8倍の決め打ちでは、本人の術式が画面の高さの4割ほどあると0.03秒で画面の外へ出てしまい、目に見えなかったため）。「画面の対角線の半分÷術式の半径」（最低2倍）を抜けきる倍率とし、そこへ0.20秒で届きます（最初はゆっくり、後半で速く）。残りの0.05秒でさらに1.3倍まで広げながら濃さを0へ。
- 濃さは最初の0.15秒は1.0、そこから0へ。
- 同時に全画面の白が0.85まで上がり、0.17秒で戻る（既にある閃光の層を使う）。
- 線の色は属性の色、芯は白。今の術式の描き方をそのまま拡大して使います。

**これがカットインの代わりです。** 自分を外から見る絵は使いません。

### 4.2 輪をくぐって奥へ伸びる（76.30〜77.50秒）

術式から騎士の核までの道筋に、術式の輪を5枚並べます。手前ほど大きく、奥ほど小さく置きます。

- 輪の大きさは、手前が画面の高さの0.42倍、奥が0.08倍。等間隔ではなく、奥ほど詰めて置くと遠く見えます。
- 魔法の本体がくぐるたびに、その輪が0.12秒だけ強く光り、輪から火花が外へ散ります。
- くぐるたびに本体を1.15倍にし、速さを1.1倍にします。5枚で約2倍になります。
- 本体そのものは、ほかの回と同じ飛翔の部品（`drawTravel`）を使います。属性、形、個数、軌道は本人の魔法のままです。

### 4.3 多段命中（77.60〜78.10秒）

当たる時刻は**固定で4回**です。77.60、77.76、77.92、78.10秒（世界の時刻）。一回目の連弾は「80ms間隔で数発、最後だけ200ms空ける」なので弾の数で時刻が変わりますが、とどめでは時刻を固定します。理由は、部品が飛ぶ時刻と体力の減り方と世界の時計のゆがみを、入力によらず同じにするためです。

- 本人の魔法の弾の数（1〜5）は、この4回へ散らします。1発なら77.60秒に当たったあと、破裂が広がって残りの3回で部品が飛ぶ形にします。5発なら77.60秒に2発当て、あとは1発ずつです。
- 当たるたびに、火の粉と破片を**手前へ**飛ばします。下向きに強く、画面の外へ抜けるまで大きくします。
- 当たるたびに騎士の部品が一つ飛びます（4.5を見てください）。
- 停止は一発目だけ。あとの3回は揺れと、騎士の上だけの白にします。全画面の白は一発目だけです。
- 実装では、これに加えて、4回の命中へ画面の外から光の筋を走らせています（左、右、上、正面の順。`FINISH_STREAK`）。命中が胸の一点だけだと画面の左右が空くためです。

### 4.4 とどめの一撃（78.50秒）

- 停止0.25秒。世界の時計が止まるので、破片も粒も空中で静止します。
- 白→属性色→白の三段。合計0.15秒。騎士の形の上だけで、全画面には出しません。全画面の白は1回だけ（0.34秒の間隔の決まりを守るため）。
- 傾き2度、寄り1.2倍、端ほど強い色のずれ。
- 核の位置から衝撃波の輪が3枚、手前へ向かって広がります。
- 0.25秒後からスロー。

### 4.5 崩れ落ちる

| 時刻（世界） | 落ちるもの | 見せ方 |
| --- | --- | --- |
| 77.60 | 肩の棘（左） | 部品を消し、その場から破片を飛ばす |
| 77.76 | 盾 | 同じ。落ちた先の床で跳ねる |
| 77.92 | 兜の角（残りの1本） | 同じ |
| 78.10 | 胸当ての残り | 同じ |
| 78.80 | 胸の核 | 砕ける。スローで見せる |
| 79.10 | 剣 | 手放して床へ。跳ねて止まる |
| 79.80〜82.00 | 体そのもの | 膝をつき、手前へ倒れる |

**倒れる向きは手前です（決定済み）。** 足元を軸に手前へ1.0ラジアン回し、同時に視点へ近づけます。近づける量は、初めの案の0.6から0.25へ浅くし（0.6まで寄せると兜の上面だけが画面いっぱいの黒い形になるため）、そのあと騎士を見上げる視点にして視点が騎士へ近づいたので、今は0.15です（`src/render/knight.ts` の `FALL_TURN` と `FALL_NEAR`）。回す角も1.0で十分に倒れて見えます。近づくので画面の中で大きくなり、迫って見えます。倒れきったら動かしません。倒れた体の一番上が画面の縦の真ん中より下に来る程度に収め、89.4秒から重なる魔導書の枠の邪魔にもなりません。

騎士は部品を組んでできています（剣と盾、表面の傷と汚れの絵も入っています）。落とすときは次のようにします。

- 盾は面、縁、鋲、帯、飾りの5種類の部品の集まり、剣は握り、柄頭、鍔、刃、切っ先の集まりです。**それぞれ親の節ごと**外して落とし、ばらばらにしません。表面の絵はそのままなので、落ちた部品も同じ見た目です。
- 兜の角は防御の回のよろめき（「同時に」は52.5秒、「順番に」は44.5秒）で1本折れているので、残りの1本を落とします。胸当ては防御の回の引き継ぎ（「同時に」は55秒、「順番に」は46秒）で外れて開いているので、その残りを飛ばします。
- 当たった場所には「属性の色の傷あと」を付けます。一回目の命中では胸に付きます。とどめでは4回の命中それぞれの部品の位置に付け、とどめの一撃で核にも付けます。倒れ始めたら（世界の80.9秒、実際の81.6秒）傷あとは0.5秒で消します。傷あとは騎士の絵の上に描く印なので、倒れる体と一緒には動かないためです。

**砕け散らせて終わりにしません。** 崩れ落ちて動かなくなる形です。

## 5. 体力を必ず0にする

体力の段は、世界の時計で動かします（一回目の段は弾が届く時刻から作られ、防御の段はよろめきの時刻に固定です）。下の表の一回目と防御の時刻は「同時に」のもので、「順番に」では一回目の命中が19.5秒、防御の段が44.5秒です。とどめの段は二つの遊び方で同じです。とどめの段を足しました（`src/render/health-bar.ts`）。

| 時刻 | 残り |
| --- | --- |
| 開始 | 100% |
| 23.5秒（一回目の命中） | 入力の量に応じて20〜45%減る |
| 52.5秒（防御で受け止めきったとき） | 10%減る |
| 77.60、77.76、77.92、78.10秒（多段命中） | そのとき残っている量の9割を、4回に等分して減らす |
| **78.50秒（とどめの一撃）** | **必ず0%** |
| 79.80秒以降 | 枠が割れて薄れ、消える |

この表の時刻は世界の時刻です。

最後の段は「残りを全部」と書くのではなく、`left: 0` と直に書きます。前の二回でどれだけ減っていても、必ず0になります。0になったあとに点滅はさせません。

**0になったあとは、枠を消します（決定済み）。** 79.80秒から0.8秒かけて枠と「遺跡の騎士」の名前を一緒に薄くし、消したら戻しません。画面には自分の術式だけが残ります。

当たった瞬間に体力の枠が0.45秒ゆれる仕組みがあり、ゆらす時刻は一覧で決めています。一回目の命中、防御のよろめき、77.60秒、78.50秒です。間の3回ではゆらしません（0.16秒おきにゆらすと震えっぱなしに見えるため）。控えめモードではゆらしません。

## 6. 前の二回から引き継ぐもの

- 一回目から光点2〜3個、防御から光点2〜3個を、とどめの回へ渡します。合わせて最大6個です。
- とどめの回の始まり（「同時に」は56秒、「順番に」は50秒）から、視界の左右の端から中央へゆっくり寄ってきて、術式のまわりを回ります。
- 引き継ぐ量は全体の20〜30%までという決まりを守り、新しく描く線の邪魔をしない薄さにします。
- 属性を変える言葉があれば新しい属性を優先し、前の属性は小さな残光だけ残します。
- 記録では、引き継いだ形と今回描いた形を別々に残します。

実装では、各回の受け渡しの時刻（「同時に」は29秒と55秒、「順番に」は24秒と46秒）に、その回の表示用の線から光点を3つまで取ります（`src/game/battle.ts`）。「順番に」の一回目は線が無いので、声で育てた円の縁から、言葉の属性の色を持つ光点を3つまで取ります（無言なら白金色を一つ）。とどめでは4秒で寄りきり、発動まで術式のまわりを回ります（`FINISH_INHERITED`）。色を持たない光点は今の回の属性の色で光ります。前の属性の小さな残光は入っていません。

## 7. 結果画面（魔導書）

90.0秒に出します。次の人が始めるまで出したままにします。まず魔法名だけを出し、0.9秒おいてから残り（術式、三件、QR、ボタン）を出します。位置は動かさず、濃さだけ変えます。

### 置き方

横長の画面を左右に分けます。

- **左（およそ6割）**：最終術式。本人が描いた線の形のまま、枠に収めて大きく見せます。戦闘中の線で背後を埋めません。枠の外は暗く沈めます。
- **右（およそ4割）**：上から順に、魔法名（大きく、明朝、ふりがな付き）、属性と用途の札、詠唱の一文、QR、確認番号、保存の状態の一行。
- **下（横いっぱい）**：一回目・防御・とどめの三件を並べます。**三件とも術式の絵を出します（決定済み）。** 各件は、左に術式の小さい絵、右に「回の名前・魔法名・ひとこと」の三行です。代表は最終魔法です。

三件の絵は、保存してある術式の点列（表示用の線）から描き直します。戦闘中の画面を写真に撮って使うのではなく、線だけを黒地に描きます。防御の回は盾の形です。

絵を三つ足すぶん、下の帯は高くなります。1920×1080では、下の帯を画面の高さの22%（約240px）取り、絵はその中で正方形（一辺およそ190px）、文字は絵の右に置きます。左の大きい術式は残りの高さに収めます。文字が小さくなりすぎたら、三件の「ひとこと」を省いて二行にします。

縦長の画面（スマートフォンでの確認用）では、上から術式、魔法名、三件（絵と文字を横並びのまま縦に積む）、QRの順に積みます。

### 文字

- 魔法名だけ明朝、ほかはゴシック。どちらも日本語用の字形。
- 1920×1080で、魔法名は72〜96px相当、三件の行は20〜24px相当から確かめます。
- 難しい言葉には小さいふりがなを付けます。実装では、魔法名のうち詠唱の辞書で読みが引ける語にだけ付けています（`src/game/record.ts` の `nameParts`）。読みを当て推量で作らないためです。
- Jevの確信度、開発用の評価値、内部の番号は出しません。
- 結果画面の見出しは「三つの魔法を放った」です。

### QRと確認番号

- QRは320px程度から確かめ、白地と余白を取ります。**背後で粒や騎士を動かしません。**
- 確認番号は6桁の数字です。何のためにあるかは次の項で説明します。QRの真下に、離れた場所の係員が読めるよう36px相当以上の大きさで出します。
- 公開ページができるまでは、QRの場所に「持ち帰りの準備中」と出し、確認番号だけ表示します。嘘のQRは出しません。

### 確認番号とは何か

遊んだ一回ごとに付ける6桁の番号です。**その人が持ち帰るものではなく、係員が「どの回の記録か」を探すための番号です。** 使い方はこうです。

- 遊んだ人が「さっきの魔法をもう一度見たい」「QRが読めなかった」と言ってきたとき、係員が結果画面や記録の一覧からこの番号で探せます。
- 公開ページができたあと、送れていない記録を係員の画面に並べるときも、この番号で見分けます。
- 公開ページの住所（URL）に使う番号とは別です。URLの番号は推測しにくい長いもの、確認番号は人が読み上げられる短いものです。

作り方は、開始のときに乱数で6桁を作り、このPCに保存済みの番号と同じなら作り直します。日付や通し番号は入れません（順番から人数が分かってしまうため）。

### 保存の状態

QRの下に一行だけ出します。

| 状態 | 表示 |
| --- | --- |
| 届いている | 持ち帰れます |
| 送信中 | 保存中。QRの先でお待ちください |
| まだ送れていない | まだ届いていません |
| 公開ページ未対応（今） | この画面でだけ見られます |
| このPCの中にも残せなかった | 保存できませんでした。この画面を閉じると消えます |

**届いていないものを「登録しました」と書きません。** 文言は `src/game/record.ts` の `DELIVERY_MESSAGES` にあります。

### 操作

- 空中で押すボタンは作りません。持ち帰りはQRだけです。
- 画面に残すのは「もう一度つくる」「最初へ戻る」の二つ。`?dev=1` のときだけ感想の回答と記録の保存も出します。
- 誰も触らないまま3分たつとタイトルへ戻ります（秒数はURLの `resultIdle` で変えられます）。QRを読む時間としては足ります。自動で流れた見本の結果は8秒でタイトルへ戻ります。

## 8. 保存と持ち帰りの段取り

三段に分けます。**作ってあるのは一段目までです。二段目（公開ページのサーバー）は、14章の1〜7が全部終わってから着手します（決定済み）。**

**一段目（作ってある）。** 魔法が確定するたびに、このPCのブラウザーの中（IndexedDB）へ保存します。「同時に」は21秒、48秒、75秒、「順番に」は17秒、40秒、75秒の三回です。確認番号を開始時に作ります。結果画面はこの保存から作ります。回線が無くても動きます。一段目だけでも展示は回せますが、持ち帰りはできません。保存は200件までで、超えたら古いものから消します（`src/game/record.ts`）。

**二段目（公開ページができたら）。** 確定のたびにサーバーへ送り、最後の魔法は75秒の確定後に送り、発動の演出中に届くようにします。90秒を待ちません。届いていれば90秒の時点でQRの先が開きます。作業の手順は [公開ページへ送る：ゲーム側の作業手順](公開ページへ送る_ゲーム側の作業手順.md) にあります。そこで次のように決めました。

- 開始前に結果ページを予約するのはやめ、送るたびに同じ公開用の番号で上書き保存してもらう。
- 公開ページへは表示用の点列と魔法の中身だけを送り、生の点列（時刻付きの手のひらの位置）と確認番号は送らない。

**三段目（会場の運用）。** 送信待ちの一覧を係員の画面に出す、回線が戻ったら同じ番号で送り直す、二重登録を番号で防ぐ、結果ページから削除できるようにする。

保存するのは、三件のレシピ、術式の点列（本人の線と表示用の線）、詠唱の文字、引き継いだ形、時刻付きの手のひらの位置、遊び方の名前（`flow`。`sequential` か `together`）です。「順番に」の一回目は線が無いので、声で育てた円の色を `voiceColors` に残し、結果画面の絵はこの色の円で描きます。遊び方の名前が無い古い記録は、一回目に `voiceColors` があれば「順番に」、無ければ「同時に」として読みます（`storedFlow`）。**カメラの映像と音声そのものは保存しません。**

## 9. 音

- 64〜72秒は主旋律を足し、音を厚くしていきます。
- 75.6秒で一度音を抜き、75.92〜76.0秒は無音にします。
- 76.0秒の発動、77.6秒からの多段、78.5秒の直撃を別の音にします。直撃の直前に短く音を弱めます。
- 崩れる音（剣が落ちる、膝をつく、倒れる）を衝撃の音と分けます。
- 84秒からは残響だけ。90秒の魔導書で静かな一音を鳴らします。
- 録音中も効果音を鳴らします。声を受け付けている間だけ、曲と効果音を8dB下げます。とどめで下げるのは、「順番に」は62〜72秒、「同時に」は56〜72秒です。

実装では、主旋律を足すところは入っていません（曲は外部の素材を1曲ループで鳴らす作り。[音素材の入れ方](音素材の入れ方.md)）。多段の命中の音は77.6秒の一回だけです。魔導書の一音は、90秒ちょうどでは結果画面へ移っていて鳴らないので、枠が浮かび始める89.4秒に鳴らします。音の時刻は `src/audio/cues.ts` にあります。

## 10. 安全と控えめモード

- 全画面の白は、発動（76.0秒）、一発目の命中（77.6秒）、直撃（78.5秒）の3回だけ。いちばん近い間隔でも0.9秒あるので、1秒に3回の決まりを守れます。間の3回の命中では全画面を光らせません。
- 白→属性色→白の三段の点滅は、騎士の形の上だけに限ります。全画面ではやりません。
- 飽和した赤の明滅は使いません。
- 控えめモードでは、揺れ、傾き、寄り、停止、色のずれを止め、閃光は3分の1にします。**スローと崩れ落ちる動きは残します**（動きが減る方向のため）。術式が視界を通り抜ける演出も残しますが、拡大を抜けきる倍率の半分に抑えます。
- 光に弱い人への配慮として、入口に注意書きを置き、係員が控えめモードへ切り替えられるようにします（今もボタンがあります）。

## 11. 負荷の見積もりと退避

1コマ10〜12msの中に収めます。重いのは76〜84秒の8秒間だけです。

| 処理 | 見積もり |
| --- | --- |
| 輪5枚（線だけ） | 0.3〜0.6ms |
| 多段命中の粒（1発あたり最大240個、合計で上限内） | 2〜5ms |
| 崩れ落ちの破片と塵 | 1〜3ms |
| 重い後処理（にじみ、色収差、歪み） | 2〜5ms |
| 騎士の立体の描き直し | 1〜3ms |

- 重い後処理は世界の時刻で75.9〜85.5秒だけにします（実際の時刻では75.9〜86.2秒あたり）。一回目と防御の「命中の2.5秒後まで」のままだと、とどめの回では80.1秒で切れてしまうので、とどめだけ余韻の始まりの1.5秒後まで伸ばしています（`src/render/composite.ts` の `postToOf`）。弱点が光るとどめの回の始まりから76秒までは、常時のにじみだけをかけます。
- 粒は派手な設定の上限（700個）を超えません。超えそうなら古いものから使い回します。
- 毎秒の表示回数を測り、55を下回ったらにじみを切り、24を下回り続けたら合成そのものを止めて元の層へ戻します。

## 13. 試験の計画

作る前に決めた計画です。今の試験は `tests/finish.test.ts`、`tests/finish-audio.test.ts`、`tests/finish-effects.test.ts`、`tests/health-bar.test.ts`、`tests/record.test.ts` と、ブラウザーの `tests/browser/play.spec.ts`、`tests/browser/finish-knight.spec.ts` などにあります。計画の一つ一つがどの試験に当たるかは、ここでは突き合わせていません。

単体の試験で先に守るもの。

- 世界の時計：止めが重なっても時刻が戻らないこと、遅くした分だけ遅れること、**一回目と防御の値が今までと完全に同じであること**（総当たりで比べる）。
- 世界の時計が、実際の時刻に対して増えるだけで減らないこと（0〜90秒を細かく刻んで確かめる）。
- 上の表の「実際の時刻」が計算と合っていること（実際の77.70で世界が77.60、78.85で78.50、79.82で79.10、90.0で89.275）。
- 遅れの合計が0.8秒を超えないこと。超えると余韻が削られるため、試験で止めます。
- ゆがみが本人の魔法（弾の数、属性、用途）で変わらないこと。
- 体力：どんな入力でも78.5秒でちょうど0になること。前の二回の減り方によらないこと。
- 回の表：三回目の場面の境目、締め切りと確定の間隔、とどめの一撃が最初の到達より後で余韻より前にあること。
- 引き継ぎ：光点が6個を超えないこと。
- 結果画面に渡す三件が、実際に確定した魔法と一致すること。
- 確認番号が6桁で、保存済みの番号と重ならないこと。

ブラウザーの試験で守るもの。

- 90秒を通して遊び、画面のエラーが出ないこと。
- 78.5秒に体力が0になり、結果画面に三件が絵つきで並ぶこと。
- 結果画面が次の開始操作まで消えないこと。
- 確認番号が6桁で出ていること。
- 魔法名が76〜84秒の間は出ず、84秒に出ること。
- 誰も触らない見本が90秒で結果まで流れ、8秒でタイトルへ戻ること。

## 15. 決まったこと

レビューで直したことも書いておきます。

- 間の小さい命中で0.06秒ずつ止めるのをやめ、止めるのは一発目（0.10秒）ととどめの一撃（0.25秒）の2回にした。仕様の「約0.1秒」を守り、止める回数が入力で変わらないようにするため。遅れの合計は0.745秒から0.725秒になった。
- 多段命中の時刻を固定の4回にした。弾の数で部品の飛ぶ時刻や体力の減り方が変わらないようにするため。
- 全画面の白の回数を、2回ではなく3回（発動、一発目、直撃）と正しく数え直した。
- 重い後処理の終わりが「命中の2.5秒後」で決まっていて、とどめの回では余韻の途中で切れることが分かったので、回の表から取るようにした。
- 回の名前と、とどめの一撃の時刻に同じ `finish` という名前を使わないことにした。
