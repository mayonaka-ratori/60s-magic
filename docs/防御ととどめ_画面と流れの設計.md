- 時間の決まり、防御の考え方、保存の項目：[設計仕様](../60秒魔法ゲーム_設計仕様.md)の1.3、1.6、1.7、4章

秒数は設計仕様の1.3をそのまま使い、動かしていません。仕様に書かれていない細かい時刻だけをここで決めています。仕様の値を変えたい箇所は「10. 決めてほしいこと」に分けて書きました。

## 結論

1. **山を三つ作り、後ろほど大きくする。** 1回目は「自分の動きが魔法になった」、防御は「自分の魔法で敵の一撃を切り抜けた」、とどめは「今までで一番大きいものを見届けた」。停止の長さ、白の濃さ、揺れ、寄り、命中の数を、おおよそ1対1.5対3の比で上げる。
2. **騎士の姿勢を3つから9つへ増やす。** 待機、ひるみ、構えを戻すに、構え、溜め、振り下ろし、弾かれる、弱点を晒す、崩れ落ちるを足す。今の騎士は40ほどの部品を組んで作ってあるので、命中のたびに兜の角、肩の棘、盾、胸当てを落とせる。ここが一番安くて効く。
3. **敵の攻撃は三発（小、小、特大）にする。** すでに入っている連弾のリズム（80ms間隔で数発、200ms空けて特大）を、そのまま敵側にも使う。予告の赤い線を床へ走らせ、接触は必ずプレイヤーの魔法が出た後に置く。
4. **とどめは1回目を大きくしたものにしない。段取りそのものを変える。** 0.32秒の完全な静止、0.08秒の暗転、術者のカットイン、多段命中、0.25倍のスロー、背景の消し込み、崩れ落ちる動きを、とどめだけに使う。
5. **60秒ちょうどで魔導書とQRを出す。** 57秒から余韻、59.4秒で枠が浮かび、60.0秒で文字とQRが入る。結果は次の人が始めるまで出したままにする。

## 6. 敵の攻撃と、それを防ぐ見せ方

### 攻撃そのもの

- 形は三日月の斬撃波。芯は白、縁は濁った赤にします。プレイヤーの魔法は属性の色なので、色だけで敵味方が分かります。
- 三発。小、小と80ms差で来て、200ms空けてから特大が来ます。
- 予告として、振り下ろしと同時に床へ赤い線を走らせます。線の先が接触点です。
- 敵弾は演出の層の中に描きます。層を増やさないので、合成と後処理がそのまま効きます。
- 接触の時刻は、プレイヤーの魔法が出た後になるよう必ず後ろへ置きます。早く描き終えても遅く描き終えても変えません。

### 防ぎ方

少しでも動いていれば必ず切り抜けます。成功度で格付けはしません。確定した魔法から見せ方だけを選びます。

| 作った魔法 | 見せ方 | 敵弾の消え方 |
| --- | --- | --- |
| 広い面、壁、氷 | 面に当たり、接触点から同心円が走る。面が一度波打つ | 左右へ砕け、かけらが床で止まる |
| 小さい球、短い線 | 凝縮した光が接触点へ飛び、正面からぶつかる | 相殺の小さな破裂が三つ |
| 炎、攻撃的な詠唱 | 炎が敵弾を包む | 黒い煙と火の粉になって落ちる |
| 雷、連弾 | 光が迎え撃ち、空中で刺さる | 複数の火花に分かれて瞬時に消える |
| 風、波 | 面の傾きに沿って滑る | 画面の外（右上）へ抜け、遠くで音だけ鳴る |
| 闇、囲う形 | 暗い穴が開き、吸い込む | 飲み込んだ分だけ穴が膨らんで閉じる |
| 拘束 | 輪が敵弾を掴んで止める | その場で砕ける |
| 強化 | 術式から出た力が押し返す | 逆向きに加速して騎士へ戻り、騎士が自分の攻撃で怯む |

どの場合も共通で入れるものは、接触の瞬間の停止、接触点の火花、自分の術式が一度強く光ること、そして「防いだ」の一言です。自分の線が働いたと分かることを優先します。全部を同じ盾に置き換えません。

全く入力がなかった回も、最低限の光の核で必ず防ぎます。画面では失敗を告げず、記録にだけ入力不足を残します。

- 弱点の光と部位の脱落は、騎士の層の中で作る。

## 8. 結果と持ち帰り（60秒以降）

### 魔導書の画面

- 左に最終術式を大きく。枠に収め、本人が描いた形のまま見せます。戦闘中の線で背後を埋めません。
- 右に魔法名（大きく、ふりがな付き）、属性と用途の札、詠唱の一文、QR、確認番号。
- 下に1回目、防御、とどめの三件を小さく並べます。代表は最終魔法です。
- QRは320px程度から確かめ、白地と余白を取ります。背後で粒や騎士を動かしません。
- 開発用の評価値とJevの確信度は画面に出しません。スマートフォン側の「魔法の詳細」へ分けます。
- 空中で「保存する」を押させる操作は作りません。持ち帰りはQRだけにします。

### 保存の段取り

1. 開始前か開始直後に、推測しにくい公開用の番号と結果ページを予約します。
2. 魔法が確定するたびに端末へ保存し、順にサーバーへ送ります。16秒、33秒、51秒の三回です。
3. 最後の魔法は51秒の確定後に送る準備を始め、発動の演出中に送ります。60秒を待ちません。
4. 60秒で魔導書を出します。正常なら、その時点でQRの先が開きます。

### 保存の状態の書き方

嘘の完了を見せません。QRの下に一行だけ出します。

| 状態 | 表示 |
| --- | --- |
| 届いている | 持ち帰れます |
| 送信中 | 保存中。QRの先でお待ちください |
| 予約も作れなかった | まだ届いていません |

端末側はブラウザー内の保存場所に残し、回線が戻ったら同じ番号で送り直します。二重登録は番号で防ぎます。係員の画面に保存待ちを出します。

### 共有

公開ページは検索に出さず、番号を知る人だけが開ける形にします。公開期間は仮に30日。結果ページから削除できるようにし、削除の権限は公開URLとは別にします。SNSへの投稿は本人が行います。動画の生成、自動投稿、公開一覧は後回しです。

## 9. 前の形を残す

- 1回目から、特徴的な光点2〜3個と線の一部を防御へ渡します。渡す量は全体の20〜30%までです。
- 防御では、その点を横へ広げ、新しく描いた線を面の外周に使います。
- とどめでは、残った点を中心へ寄せ、新しい線を発射の向きと外周に使います。
- 属性を変える言葉があれば新しい属性を優先し、前の属性は小さな残光だけ残します。
- 古い線を全部消して別の完成図を出すことはしません。引き継いだ形と今回描いた形は別々に保存します。

## 10. 安全と控えめモード

- 1秒に3回を超える点滅は作りません。全画面の白は0.34秒の間隔を空ける仕組みが既に入っているので、とどめの三段の点滅は騎士の形の上だけに限り、全画面は1回だけにします。
- 飽和した赤の明滅は使いません。敵の赤は暗い赤にとどめます。
- 控えめモードでは、揺れ、傾き、寄り、停止、色のずれを止め、閃光は3分の1にします。スローと崩れ落ちる動きは残します（動きが減る方向のため）。入口に注意書きを置き、係員が切り替えられるようにします。
- 重い後処理は、三つの山の前後だけに限ります。1回目は16.9〜21秒、防御は33.5〜38秒、とどめは51.5〜57.5秒を目安にします。それ以外はビネット、グレイン、弱いブルームだけにします。
- 毎秒の表示回数を測り、55を下回ったらブルームを切り、24を下回り続けたら合成そのものを止めて元の層へ戻します。この退避はすでに入っているので、時間帯だけ足します。

## 11. 実装の当たりどころ

今の作りは、演出が時刻だけで決まる純粋な計算になっています。この性質を壊さずに回を増やすのが要点です。

| 直すところ | 今 | どうするか |
| --- | --- | --- |
| 60秒の進行役 | `src/game/session.ts` が24秒1回分。場面の切り替わりが数値で埋め込んである | 回ごとに七つの時刻を持つ表を作り、それを三つ並べる。1回目の値は今のまま |
| 演出の基準時刻 | `src/render/effects/screen.ts` の放出17秒と命中18.5秒が定数 | 回ごとの基準時刻を渡す形にする。純粋な計算のままにして試験しやすさを保つ |
| 騎士の姿勢 | `src/render/knight.ts` が18.5秒の命中を前提にしている | 出来事の一覧（時刻、種類、強さ、向き）を受け取る形にする。姿勢の表を9つへ増やす |
| 敵の攻撃 | ない | 演出の部品として足す。予告、三発の斬撃波、接触、防ぎ方の8種類 |
| 部位の脱落 | ない | 部品を隠す、または落として床で止める。素材は要らない |
| 体力表示 | 1回分 | 三回分の段階に分け、とどめで0にする |
| 引き継ぎ | ない | 光点と線の一部を次の回へ渡す。引き継いだ形は別に保存する |
| 保存とQR | ない | 予約、三回の保存、送信待ち、状態の表示、結果ページ |

## 12. 作る順番

段階の区切りは設計仕様の5.3に合わせています。途中で止めても壊れない順にしました。

| 順 | 作るもの | できたと言える条件 |
| --- | --- | --- |
| 1 | 60秒の進行役と、仮の敵での三回つなぎ | 24秒、40秒、60秒で場面が切り替わり、三回とも描いて唱えて発動する |
| 2 | 騎士の姿勢9つと部位の脱落 | 構え、溜め、振り下ろし、弾かれ、弱点、崩れが見える。角と盾と胸当てが落ちる |
| 3 | 敵の攻撃と防ぎ方8種類 | 小さい動き、片手、攻撃的な詠唱でも全件が切り抜ける。魔法ごとに見せ方が違う |
| 4 | 前の形の引き継ぎ | 1回目の光点が防御ととどめに見える。新しい入力の邪魔をしない |
| 5 | とどめの段取り | 静止、暗転、カットイン、多段、スロー、崩れ、余韻が順に出る。60秒で結果へ渡る |
| 6 | 結果画面とQRと保存 | 画面で出た魔法と、QRの先の魔法が一致する。未保存を保存済みと表示しない |
| 7 | 会場の条件で調整 | 初見の人での確認と、4時間の連続運転 |

1と2は今の作りの延長で、素材も要りません。3が体験の要です。5は素材（術者の立ち絵と着弾のコマ絵）があると良くなりますが、なくても作れます。

## 13. 決めてほしいこと

1. **とどめの停止を0.25秒まで伸ばしてよいか。** 仕様の1.7は「約0.1秒」です。大型ゲームの目安はとどめで0.17〜0.3秒なので、最後の1発だけ伸ばしたいです。1回目と防御は今のままにします。
2. **敵の攻撃は三発でよいか。** 一発だけにすると分かりやすく、三発にすると防いだ実感が強くなります。三発を勧めます。
3. **倒れ方をどちらにするか。** 部位が飛んで砕けるか、膝をついて動かなくなるか。展示の後味が変わります。砕ける方が派手で、膝をつく方が誰でも見やすいです。
4. **術者のカットインを入れるか。** 0.3秒だけ差し込む立ち絵です。生成の指示文は用意してあります。素材を作るかどうかを決めてください。
5. **結果ページのサーバーをいつ用意するか。** 当面は端末の中だけで結果を見せ、QRは後から足す形にもできます。展示の日程しだいです。
6. **体力表示を残すか。** 仕様では残す場合は演出に合わせて減らします。勝敗の判定には使いません。消してしまう選び方もあります。

この6点が決まれば、順番の1から着手できます。1と2で二日、3で三日、4で一日、5で三日、6で四日が目安です（実機での確認は含みません）。
