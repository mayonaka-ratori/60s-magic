# 大型バトル演出：全面更新の提案

2026年9月20日。モンスターハンター、エルデンリング、ゴッド・オブ・ウォー、FF16、格闘ゲームなどの大型バトルの演出を三つの切り口（打撃の手応えと大技の段取り、魔法の絵作り、画面全体の効果の技術）で調べ、この展示ゲームに合わせて統合した提案です。前段の[調査と検討](演出のバリエーション_調査と検討.md)と[実装の説明](演出のバリエーション_実装.md)の続きです。

2026年9月21日に「まだ手応えが足りない」「左右の余白が使えていない」という指摘を受け、一撃の数値を上げ、敵が自分から動く場面を足しました。今の数値はこの文書ではなく[画面全体を使う演出と、敵の圧](画面全体と敵の圧_実装.md)にあります。演出のコードの不具合の洗い出しと直しは[演出コードレビュー](演出コードレビュー.md)にあります。

提案のときに決めてほしいとした4点は、次のように決まりました。

1. 段階4まで進める。作った。
2. 素材。カットインはやめた。騎士はアプリの中で組み立てた立体にした。着弾のコマ絵と、騎士をもっと精細にする素材は、指示文だけ用意してあり、作るかどうかは決めていない。
3. 派手さの上限。全画面の白は0.85まで、雷の明滅は毎秒3回以下。
4. 控えめモードは画面のボタン（「演出を控えめにする」）と`?calm=1`の両方で切り替えられる。

合成があると、描画の遅い環境（この作業環境のように毎秒1コマ程度）ではブラウザーの試験の時刻がずれて落ちることがありました。`npm run test:browser`が落ちたときは、合成の重さも疑ってください。

以下は提案を書いたときの調査の中身です。作り方の細部（提案の段階ごとの手順と、当時の実装との差の表）は、作り終えたので削りました。

## 1. 大型ゲームから学ぶ要点

### 手応えは「緩急」でできている

どの作品も「加速、一瞬の減速、解放、静止」の順で見せます。ずっと派手だと逆に弱く見えます。

| 段階 | 時間の目安 | 定番の手法 |
| --- | --- | --- |
| 溜め | 1〜2秒 | 粒が中心へ吸い込まれる。音が上がる。周りが暗くなり術者だけ明るい。カメラがゆっくり寄る |
| 溜めの頂点 | 0.2〜0.4秒 | 一瞬だけ完全に止まる。ここの「間」が解放を強く見せる |
| 放出の直前 | 0.05〜0.1秒 | 全部を消して暗くする。次の閃光が数倍強く見える |
| 発動 | 0.1〜0.3秒 | 閃光、色を抜く、カットイン |
| 飛翔と多段命中 | 1〜2.5秒 | 命中ごとに小さい停止と揺れを積む。間隔は等間隔にしない（80ms×数発、200ms空けて特大1発） |
| とどめ | 0.3〜0.6秒 | 一番長い停止、その後スローモーション（0.25倍、0.3秒）、通常へ戻す |
| 余韻 | 1〜2秒 | 煙と塵が落ちる。カメラが引く。音は残響だけ |

### 一撃の手応えの数値

| 要素 | 弱 | 強 | とどめ |
| --- | --- | --- | --- |
| 停止 | 2〜4コマ（33〜67ms） | 5〜8コマ（80〜130ms） | 10〜18コマ（170〜300ms） |
| 揺れ | 2〜4px | 6〜12px、0.15〜0.3秒、20〜30Hz | 12px以上、回転0.5〜2度 |
| 白点滅 | 2〜4コマ | 6コマ | 白、属性色、白の三段 |
| 火花と斬撃線 | 0.1〜0.25秒 | 同じ | 二重三重の輪をずらす |

揺れは打撃の向きに沿わせて指数的に減らします。乱数の震えだけだと安く見えます。ゴッド・オブ・ウォーはあえて揺れを減らし、音と動きで衝撃を出しています。「揺らせば強い」ではありません。

音は体感の半分以上です。低音（重さ）、中音（肉と金属）、高音（鋭さ）の三層を重ね、映像より数ms早く鳴らし、連打では音の高さを毎回少し変えます。

### 魔法の絵作り

魔法は一枚絵でなく、芯（ほぼ白）、縁（属性色）、にじみ、内部の流れ、周りの歪み、粒の3〜5層でできています。属性色は縁だけに置き、芯は白にします。彩度の高い芯は弱く見えます。

同じ形でも属性が一目で分かるのは、縁の色、粒の向き（炎は上、闇は内、風は回転、氷は静止、雷は不規則、光は外へ直線）、そして「消え方」（炎は煙が残る、氷は砕けて落ちる、雷は瞬断、風はすっと消える、闇は吸い込まれる）の三つです。出し方より消し方の方が属性が伝わります。

エルデンリングの彗星アズールが強く見えるのは、光線そのものより「3秒溜めてから撃ち続ける」時間設計と、着弾点が画面を白く飛ばすほど明るいことです。

二つの属性の合わせ方は平均色にしないこと。「明るさを1.5倍にして白い閃光を足す（増幅）」「中間色の球状の爆発（爆発）」「二色を交互に明滅させる（持続）」の三型で足ります。

### 画面全体の効果の基準

| 効果 | 向く場面 | 抑え方 |
| --- | --- | --- |
| 全画面の白 | 大技の発動と命中の瞬間 | 立ち上がり2〜3コマ、戻り8〜15コマ。濃さは0.6〜0.85まで |
| ビネット（縁を暗く） | 溜め、とどめ、余韻 | 常時0.2〜0.35、衝撃時0.5〜0.7。ゆっくり入れてゆっくり抜く |
| 色のずれ | 命中の瞬間、咆哮 | 0.1秒以内。端ほど強く、中心は0 |
| 放射状のぼかし | 大技の飛翔、スロー中 | 中心から外だけ。0.2〜0.4秒 |
| 寄り（拡大） | 命中 | 1.05〜1.2倍を0.3秒で戻す |
| 傾き | 特大の一撃だけ | 0.5〜2度、0.2秒で戻す。一回の魔法で1〜2回まで |
| 背景の消し込み | 大技の発動 | 背景を暗く、または単色にし、騎士と魔法だけ残す。2Dで一番安く効く |

### 安全（展示では必須）

- 1秒間に3回を超える点滅を作らない（WCAG 2.3.1）。全画面の強い明滅は0.5秒に1回、連続3回まで。飽和した赤の明滅は避ける。
- 画面の揺れと閃光を切れる「控えめモード」を用意し、係員が切り替えられる導線を置く。入口に注意書き。
- 提案を書いた時点では、雷の命中が毎秒20回の明滅で作られていた。今は毎秒3回以下に落としてある。

## 2. 負荷の目安

1280×720、ノートPCの内蔵GPUで、1コマの描画に使えるのは10〜12msです。

| 処理 | 費用 |
| --- | --- |
| CSSのtransform（層ごと） | ほぼ無料 |
| 全画面の塗り1回 | 0.3〜0.8ms |
| 4分の1縮小のぼかしを戻す（ブルームの実用解） | 0.5〜1ms |
| canvasからWebGLへの転送（1枚） | 1〜2.5ms |
| Babylonの後処理1段（色収差、グレイン、ビネット） | 0.3〜0.8ms |
| Babylonのブルーム（半解像度） | 1.5〜3ms |
| 被写界深度、モーションブラー | 3〜6ms。常時は避け、一瞬だけ |
| 粒700〜1100個 | 2〜5ms |

常時かけるのはビネット、グレイン、弱いブルームまで。色収差、放射状のぼかし、歪みは命中の0.5秒だけに限れば60fpsを保てます。長時間展示では熱で性能が落ちるので、fpsを常に測って55を下回ったら設定を一段下げる自動の退避を入れます。
