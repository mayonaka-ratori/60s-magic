# 大型バトル演出：全面更新の提案

2026年9月20日。モンスターハンター、エルデンリング、ゴッド・オブ・ウォー、FF16、格闘ゲームなどの大型バトルの演出を三つの切り口（打撃の手応えと大技の段取り、魔法の絵作り、画面全体の効果の技術）で調べ、この展示ゲームに合わせて統合した提案です。前段の[調査と検討](演出のバリエーション_調査と検討.md)と[実装の説明](演出のバリエーション_実装.md)の続きです。

## 結論

1. **土台の直しを先にやる。** 時計を一つにして命中の停止を世界全体に効かせる、揺れを「向き付き＋減衰」に変える、寄り（拡大）を足す、閃光とビネットをHTMLの層に出す。手間は小さく、体感の変化が一番大きい。
2. **騎士の反応を作り込む。** 白飛びの点滅、吹き飛びと回転、残像、輪郭の発光、背景より大きく揺らす。ここまでで手応えの8割が上がる見込み。
3. **その上で、画面全体の後処理は「合成専用のBabylonシーンを最前面に足す」案で入れる。** 背景、騎士、演出canvasを板に貼って一台のカメラで合成し、ブルーム、色収差、歪み、グレインをかける。既存の2D演出コードは捨てない。WebGLが使えないときは1〜2の状態へ落とす。
4. **派手さは「大技のときだけ、短く、一回」。** ずっと派手だと弱く見える。放出の直前に0.08秒の完全な暗転と静寂を入れる、命中で60〜90msの停止、とどめだけ長く。点滅は1秒に3回まで、全画面の白は濃さ0.6〜0.85まで、控えめモードを係員が切り替えられるようにする。

## 1. 大型ゲームから学ぶ要点

### 手応えは「緩急」でできている

どの作品も「加速、一瞬の減速、解放、静止」の順で見せます。ずっと派手だと逆に弱く見えます。

| 段階 | 時間の目安 | 定番の手法 |
| --- | --- | --- |
| 溜め | 1〜2秒 | 粒が中心へ吸い込まれる。音が上がる。周りが暗くなり術者だけ明るい。カメラがゆっくり寄る |
| 溜めの頂点 | 0.2〜0.4秒 | 一瞬だけ完全に止まる。ここの「間」が解放を強く見せる |
| 放出の直前 | 0.05〜0.1秒 | 全部を消して暗くする。次の閃光が数倍強く見える |
| 発動 | 0.1〜0.3秒 | 閃光、色を抜く、カットイン |
| 飛翔と多段命中 | 1〜2.5秒 | 命中ごとに小さい停止と揺れを積む。間隔は等間隔にしない（80ms×数発、200ms空けて特大1発） |
| とどめ | 0.3〜0.6秒 | 一番長い停止、その後スローモーション（0.25倍、0.3秒）、通常へ戻す |
| 余韻 | 1〜2秒 | 煙と塵が落ちる。カメラが引く。音は残響だけ |

### 一撃の手応えの数値

| 要素 | 弱 | 強 | とどめ |
| --- | --- | --- | --- |
| 停止 | 2〜4コマ（33〜67ms） | 5〜8コマ（80〜130ms） | 10〜18コマ（170〜300ms） |
| 揺れ | 2〜4px | 6〜12px、0.15〜0.3秒、20〜30Hz | 12px以上、回転0.5〜2度 |
| 白点滅 | 2〜4コマ | 6コマ | 白、属性色、白の三段 |
| 火花と斬撃線 | 0.1〜0.25秒 | 同じ | 二重三重の輪をずらす |

揺れは打撃の向きに沿わせて指数的に減らします。乱数の震えだけだと安く見えます。ゴッド・オブ・ウォーはあえて揺れを減らし、音と動きで衝撃を出しています。「揺らせば強い」ではありません。

音は体感の半分以上です。低音（重さ）、中音（肉と金属）、高音（鋭さ）の三層を重ね、映像より数ms早く鳴らし、連打では音の高さを毎回少し変えます。

### 魔法の絵作り

魔法は一枚絵でなく、芯（ほぼ白）、縁（属性色）、にじみ、内部の流れ、周りの歪み、粒の3〜5層でできています。属性色は縁だけに置き、芯は白にします。彩度の高い芯は弱く見えます。

同じ形でも属性が一目で分かるのは、縁の色、粒の向き（炎は上、闇は内、風は回転、氷は静止、雷は不規則、光は外へ直線）、そして「消え方」（炎は煙が残る、氷は砕けて落ちる、雷は瞬断、風はすっと消える、闇は吸い込まれる）の三つです。出し方より消し方の方が属性が伝わります。

エルデンリングの彗星アズールが強く見えるのは、光線そのものより「3秒溜めてから撃ち続ける」時間設計と、着弾点が画面を白く飛ばすほど明るいことです。

二つの属性の合わせ方は平均色にしないこと。「明るさを1.5倍にして白い閃光を足す（増幅）」「中間色の球状の爆発（爆発）」「二色を交互に明滅させる（持続）」の三型で足ります。

### 画面全体の効果の基準

| 効果 | 向く場面 | 抑え方 |
| --- | --- | --- |
| 全画面の白 | 大技の発動と命中の瞬間 | 立ち上がり2〜3コマ、戻り8〜15コマ。濃さは0.6〜0.85まで |
| ビネット（縁を暗く） | 溜め、とどめ、余韻 | 常時0.2〜0.35、衝撃時0.5〜0.7。ゆっくり入れてゆっくり抜く |
| 色のずれ | 命中の瞬間、咆哮 | 0.1秒以内。端ほど強く、中心は0 |
| 放射状のぼかし | 大技の飛翔、スロー中 | 中心から外だけ。0.2〜0.4秒 |
| 寄り（拡大） | 命中 | 1.05〜1.2倍を0.3秒で戻す |
| 傾き | 特大の一撃だけ | 0.5〜2度、0.2秒で戻す。一回の魔法で1〜2回まで |
| 背景の消し込み | 大技の発動 | 背景を暗く、または単色にし、騎士と魔法だけ残す。2Dで一番安く効く |

### 安全（展示では必須）

- 1秒間に3回を超える点滅を作らない（WCAG 2.3.1）。全画面の強い明滅は0.5秒に1回、連続3回まで。飽和した赤の明滅は避ける。
- 画面の揺れと閃光を切れる「控えめモード」を用意し、係員が切り替えられる導線を置く。入口に注意書き。
- 今の雷の命中は毎秒20回の明滅で作られている。面積は小さいが、実機で確認し、毎秒3回以下に落とすのが確実。

## 2. 今の実装との差

| 項目 | 今 | 大型ゲームの水準 | 差 |
| --- | --- | --- | --- |
| 停止 | 演出の粒だけ止まる。騎士と術式は止まらない | 世界全体が止まる | 時計を一つにする必要がある |
| 揺れ | 平行移動だけ。固定の波で毎回同じ震え | 向き付き、回転と拡大を混ぜ、なめらかな乱数で減衰 | 作り直し |
| 寄り | ない | 命中で1.1倍、溜めでゆっくり寄る | 新規 |
| 閃光 | 単色のべた塗り、直線で減衰 | 明るい所がにじむ。立ち上がり速く戻り遅く | HTMLの層へ出し、形を変える |
| 暗転 | 演出canvas内の放射グラデーション | 背景の彩度も落とし、術者だけ明るい | 彩度の操作を足す |
| 色のずれ | 自分の絵を左右に重ねるだけ。背景に効かない | 赤と青に分かれ、端ほど強い | WebGLの後処理が要る |
| 騎士の反応 | 3姿勢の切り替えと縦横の押し潰し。白点滅は明るさ1.7倍止まり | 白飛び、吹き飛び、回転、残像、輪郭の発光 | 作り込み |
| 揺れの適用 | 全層が同じ量で動く。背景に余白がなく端に黒帯が出る | 手前ほど大きく動く | 騎士を1.3倍、背景に1.03倍の余白 |
| 動きを減らす設定 | 騎士の呼吸と傾きだけ | 揺れ、閃光、色のずれ、停止すべてに効く | 設定を画面全体の計算に通す |
| 素材 | 生成画像1枚の騎士、背景1枚 | カットインの立ち絵、着弾のスプライト、部位の分かれた敵 | 素材の追加 |

今の作りで良い点もあります。画面全体の効果が時刻だけで決まる純粋な計算なので再現性が高いこと、粒が上限付きの置き場で管理されていること、解像度が1.5倍で頭打ちにしてあること、演出canvasが最前面なので暗転と閃光が背景と騎士にも見た目上は効いていることです。

## 3. 提案の全体像

段階ごとに独立して価値があり、途中で止めても壊れません。

### 段階1：時計と揺れの土台（手間：小。効果：大）

- 演出、騎士、術式の三つが同じ「演出の時計」を見るようにし、命中の停止で世界全体が止まるようにする。停止は弱60ms、強90ms、とどめ200ms。
- 揺れを「衝撃の強さ（0〜1）を一つ持ち、毎秒減らし、その二乗で揺れを出す」方式にし、なめらかな乱数で平行移動、回転（最大1度）、拡大（最大1.03倍）を同時に動かす。打撃の向きへ最初に押す。
- 寄りを足す。命中で1.1倍を0.3秒で戻す。溜めの後半でゆっくり1.03倍まで寄る。
- 背景と騎士に1.03倍の余白を常にかけ、端の黒帯を防ぐ。騎士は背景より1.3倍大きく揺らす。
- 放出の直前に0.08秒の完全な暗転と静寂を入れる。
- 「動きを減らす」設定と控えめモードを画面全体の計算に通す。有効なら揺れ0、閃光は3分の1、色のずれ0、停止0。

### 段階2：閃光、ビネット、グレインをHTMLの層へ（手間：小。効果：中）

- 演出canvasの塗りをやめ、全層の上に三枚のdivを置き、透明度だけ毎コマ変える。描画の費用がほぼゼロになり、背景にも確実に効く。
- 閃光は立ち上がり2コマ、戻り10コマの非対称に。中心から広がる形にして四隅は0.5以下。
- ビネットは常時0.25、溜めの後半と命中で0.6。
- 暗転で背景の彩度を落とし、術者と魔法だけ色を残す（CSSの`filter: saturate()`）。

### 段階3：騎士の反応（手間：中。効果：大）

- 白飛びの点滅（画像の形で白を重ねる。白、属性色、白の三段）。
- 吹き飛び（奥へ0.15秒で押し、0.35秒で戻る）と回転（±3度）。
- 直前3コマの位置に白いシルエットの残像。
- 輪郭の発光（属性色で9方向にずらして描き、上に本体）。
- 反応の段階化（怯み、よろめき、転倒）。同じ魔法でも入力の量で反応が変わる。
- 体力バーを二層に（即減る本体と、0.3秒遅れて追う赤い残り）。

### 段階4：合成専用のBabylonシーン（手間：大。効果：大）

- 背景、騎士、演出canvasを板に貼ったテクスチャとして正射影カメラで並べ、一台のカメラにブルーム、色収差（端ほど強い）、グレイン、ビネットの後処理と、衝撃波の歪みの自作シェーダーをかける。術式のBabylon描画は同じシーンに統合する。
- 毎コマのテクスチャ転送は合計2〜5ms。騎士は姿勢が変わった時だけ更新する。後処理は命中前後の数秒だけ有効にする。
- WebGLの初期化に失敗したら段階1〜3の状態へ落とす退避経路を残す。
- 全部をWebGLで描き直す案は、約900行の2D演出を書き直すことになり展示までの手間が大きすぎるため採らない。

### 段階5：素材と最後の魔法（手間：素材次第）

- カットインの立ち絵1枚と、着弾の爆発スプライト1枚。素材はこの2点が費用対効果最大。
- 騎士を部位（胴、頭、腕、剣）に分けた素材か、立体モデル1体（待機、被弾、よろめきの3動作）。立体なら段階4の板をモデルに差し替えるだけで済む。
- 最後の魔法の多段命中（詰めて、空けて、落とす）、とどめのスロー、敵が崩れる動き、背景の消し込み。

### 属性と魔法の絵作り（段階1〜3と並行）

- 全魔法を「芯は白、縁は属性色」の二重構造に統一する。
- 属性ごとの「消え方」を作る（炎は煙、氷は砕けて落ちる、雷は瞬断、風はすっと、闇は吸い込み）。
- 地面の跡（焦げ、霜、亀裂）を2秒かけて薄れさせ、余韻の後半を持たせる。
- 二属性の合わせ方を三型（増幅、爆発、持続）にする。今の「飾り色」は縁と粒の色を交互にする持続型に近いので、増幅と爆発を足す。

## 4. 負荷の目安

1280×720、ノートPCの内蔵GPUで、1コマの描画に使えるのは10〜12msです。

| 処理 | 費用 |
| --- | --- |
| CSSのtransform（層ごと） | ほぼ無料 |
| 全画面の塗り1回 | 0.3〜0.8ms |
| 4分の1縮小のぼかしを戻す（ブルームの実用解） | 0.5〜1ms |
| canvasからWebGLへの転送（1枚） | 1〜2.5ms |
| Babylonの後処理1段（色収差、グレイン、ビネット） | 0.3〜0.8ms |
| Babylonのブルーム（半解像度） | 1.5〜3ms |
| 被写界深度、モーションブラー | 3〜6ms。常時は避け、一瞬だけ |
| 粒700〜1100個 | 2〜5ms |

常時かけるのはビネット、グレイン、弱いブルームまで。色収差、放射状のぼかし、歪みは命中の0.5秒だけに限れば60fpsを保てます。長時間展示では熱で性能が落ちるので、fpsを常に測って55を下回ったら設定を一段下げる自動の退避を入れます。

## 5. 決めてほしいこと

1. **段階4（合成用のBabylonシーン）まで進めるか。** 段階1〜3だけでも手応えは大きく変わります。段階4は色収差、歪み、本物のブルームのためで、手間は大きめです。
2. **素材を用意するか。** カットインの立ち絵、着弾のスプライト、騎士の部位分けか立体モデル。生成画像で作るか、外部素材を買うか。
3. **派手さの上限。** 展示で多くの人が見るため、全画面の白は0.6〜0.85のどこまで許すか、雷の明滅を毎秒3回以下に落としてよいか。
4. **控えめモードの導線。** 画面上のボタンにするか、係員だけが使うURLの指定にするか。

この4点が決まれば、段階1から着手できます。段階1と2は一日、段階3は二日、段階4は一週間程度が目安です（実機での確認を含まない）。

## 進み具合

- 段階1〜3は実装済み（2026年9月20日）。停止が世界全体に効く一つの時計、衝撃の強さで減る向き付きの揺れ（傾きと拡大も少し）、寄り、放出直前の暗転、背景の彩度、閃光とビネットとグレインのHTMLの層、控えめモードのボタン、雷の明滅を毎秒3回以下に、騎士の白飛び（白、属性色、白の三段。その間はずっと塗るので点滅ではない）と吹き飛びと回転、残像、輪郭の発光、反応の段階化、二層の体力表示。単体テストと回帰のブラウザーテスト、ビルドが通っている（件数は[実装と確認の記録](実装と確認の記録.md)）。実機での見え方と負荷は未確認。
- 段階4は実装済み。最前面の一枚のcanvasに背景、騎士、術式、演出を板として並べ、一台のカメラにブルーム（放出で3倍、命中で5倍）、端ほど強い色収差、衝撃波の歪みをかける。後処理は16.9〜21秒だけ。WebGLが作れないときと `?composite=0` では段階1〜3の状態に戻る。fpsが55を下回るとブルームを切り、24fps未満が続くと合成そのものを止めて元の層へ戻す。負荷は実機で未測定。なお、この作業環境（ソフトウェア描画で毎秒1コマ程度）では合成ありだとブラウザー試験のJevの1件が時刻ずれで落ちる。`?composite=0` では通る。実機では起きない見込みだが、`npm run test:browser` が落ちる場合は合成の重さを疑うこと。
- 魔法の絵作りも実装済み。芯は白で縁だけ属性色、属性ごとの消え方（炎は煙、氷はかけらが床で止まる、雷は瞬断、風は流れて消える、光は減速、闇は吸い込み）、属性ごとの地面の跡、二属性の三型（増幅、爆発、持続）、連弾の「80ms間隔で数発、200ms空けて特大」。
- 2026年9月20日、カットインの立ち絵は使わないことになった。主観視点のゲームで、自分を外から見る絵を入れないため。とどめの見せ方は[防御ととどめの設計](防御ととどめ_画面と流れの設計.md)の5章に置き換えた。
- 素材は生成の指示文を用意した。`docs/references/カットイン立ち絵_生成の指示.md`、`着弾スプライト_生成の指示.md`、`騎士の部位分けと立体化_生成の指示.md`。画像を置いたあとに読み込みと表示の処理を作る。
