## 段階ごとの進み具合

段階の区切りは設計仕様の「5.3 作業の順序と途中の合格条件」に合わせています。

| 段階 | 内容 | 今の状態 |
| --- | --- | --- |
| 第一段階 | 手の軌跡と蓄積から発動まで | 実装済み。マウスと合成音声ではMacの実機で確認済み。人の手と声、5人に遊んでもらう確認は未実施 |
| 第二段階 | 同時の描画・詠唱とJevの12問 | 実装済み。試験用の返事で確認済み。Jevの実通信は一回だけ採用を確認 |
| 第三段階 | 3回とも成功する90秒 | 実装済み（実機は未確認）。三回とも遊べ、90秒で魔導書が出る。とどめの見せ方と騎士の崩れ落ちは別途。細かい設計は[とどめと結果](とどめと結果_詳細設計.md) |
| 第四段階 | 魔法部品と最後の演出 | 一部着手。六属性の形と消え方、派手さの段階、画面全体の効果、騎士の反応、合成の後処理まで実装済み（[提案と進み具合](大型バトル演出_全面更新の提案.md)）。24問、最後の魔法、素材の取り込みは未着手 |
| 第五段階 | 記録と持ち帰り | 一段目まで実装済み（実機は未確認）。三件をこのPCのブラウザーの中へ保存し、確認番号と魔導書を出す。QRの先の公開ページと静止画保存は未着手。段取りは[とどめと結果](とどめと結果_詳細設計.md)の8章 |
| 第六段階 | 会場条件で調整 | 未着手。実機での確認と4時間の連続運転 |

## 文書を足すとき

- 段階が進んだら上の表を直し、`第二段階の実装と確認.md` のように段階ごとの記録を足します。
- 作った部分の説明は `docs/` の直下、画像を作った指示文は `docs/references/` に置きます。
- 新しい文書を足したら、この一覧にも行を足します。作業の経過は「実装と確認の記録」に短くまとめ、文書は今の状態が分かる形に保ちます。
