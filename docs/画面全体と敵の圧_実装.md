# 画面全体を使う演出と、敵の圧：実装

2026年9月21日。「大型モンスターと戦うゲームとしてエフェクトが足りない」「左右の余白が使えていない。描いた術式が中央に縮められる」という指摘を受けて作った部分の説明です。[大型バトル演出：全面更新の提案](大型バトル演出_全面更新の提案.md)の続きにあたります。

秒数は `src/game/rounds.ts` の表から作っています。遊び方で時刻が変わる所は「同時に」と「順番に」を並べて書きます。

## 術式は描いた場所と大きさのまま

描く締め切りのあとも、描いた形は描いた場所に、描いた大きさのまま残ります。締め切りから発動までの間に、置く場所へ滑らかに移ります。

- 小さく描いたとき（幅が画面幅の28%未満で、高さも18%未満）だけ、どちらかが下限に届くまで広げます（上限2.2倍）。
- 上の体力表示の帯（14%）、下の案内文の帯（12%）、左右の端（2%）にかかるときだけ中へ寄せます。
- 置ける範囲より大きく描いたときだけ、収まるぶんだけ縮めます。
- 何も描いていないときは下寄りの中央（防御の回は狙いの印の高さ）に置きます。

描く締め切りは、「同時に」ではどの回も入力の締め切りと同じです（一回目は18秒）。「順番に」では一回目が声だけで線を描かないので、声で育つ円を下寄りの中央に置きます。とどめの回は62秒で描くのを締め切り、そこから発動の76秒までかけて置く場所へ移ります。

防御の回も同じ決まりで、盾は描いた線からそのまま作るので、術式と盾が重なります。結果画面の縮小図は別の決まりで、枠に収まるように縮めます。

## 弾は術式の光点から出て、画面の端へ膨らんでから騎士へ寄る

術式には最大12個の光点があり、これを弾の出どころにしています。連弾は光点から均等に選んで1発ずつ別の場所から出ます。放出の破裂、衝撃波の輪、放射状の線、飛び出す粒も出どころごとに（小さめにして）出ます。弾は道のりの6割まで画面の端の方へ膨らみ（出どころが左なら左へ、右なら右へ、上なら上へ。大きさは画面幅の20〜35%）、残りで一気に騎士へ寄ります。到着は必ず騎士の胸の一点です。螺旋、放射、周回、追尾の違いはこの上に載せています。

光線は口の幅を術式の横幅の0.6倍にして、騎士に向かって絞る台形です。収束の言葉が強いほど早く細くなります。壁は描いた線の輪郭そのものを面にし、結界は術式に外接する楕円、波は術式の横幅いっぱいの帯が進みます。二属性を唱えたときは、術式の左半分の光点から主属性、右半分から二つ目の属性が出て、騎士のところで一つになります。

## 蓄積は画面全体から吸い込む

入力の締め切りから発動まで（多くの回で4秒、「順番に」の防御の回だけ3秒）、粒は画面の四辺から生まれて術式の光点と中心へ流れ込みます。術式の下の床全体に属性の色の楕円の明かりが敷かれ、蓄積が進むほど明るくなります（濃さは最大0.35）。地面から昇る光の筋は術式の横幅いっぱいに散り、魔法陣は術式の横幅の半分まで大きくなります（画面の高さの30%が上限）。たくさん描いて唱えた人（入力の量が0.5以上）には、光点ごとの小さな陣も出ます。

## 一撃の手応え

| 項目 | 値 |
| --- | --- |
| 命中で止める長さ | 弱0.10秒、強0.14秒。派手さが上限の3のときだけ0.2秒。防御の回はいつも強 |
| 単発の攻撃の命中の止め | 3回。命中、命中の0.08秒後（破裂）、0.2秒後（衝撃波が抜ける）。合計の遅れは強で0.21秒 |
| 揺れの基準（派手、最大） | 14画素、22画素 |
| 命中の寄り | 1.18倍 |
| 傾きの最大 | 2度 |
| 全画面の白の上限 | 0.85。派手の設定のふつうの魔法の命中で約0.75 |
| 命中の最初の2コマ | 画面の色を反転した一枚（アニメの手法）。同じ一回の閃光の一部として数え、明滅の回数は増やさない |

見た目の側も三段に合わせています。単発の攻撃は、命中から0.08秒までは白い芯の小さな破裂だけ、0.08秒で破裂と粒と火花と亀裂、0.2秒で輪と、画面の横幅を超えて抜ける輪が出ます。連弾は弾ごとに届きます。

## 命中の跡は回の終わりまで残る

床の跡（焦げ、霜、焼けた筋など）は、その回の受け渡しの1.5秒前から薄れ始め、受け渡しで消えます。とどめの回だけは余韻の始まりから2秒かけて薄れます。

命中で画面の左右の端の近く（横位置7%と93%）に立つ柱を属性の色で0.25秒照らし、柱の上から石の破片が1.5秒かけて落ちます。破裂の粒の5つに1つは画面の左右の端まで抜けます。とどめの4回の命中には、左、右、上、正面の4方向から騎士へ走り込む光の筋が付きます。

騎士の胸にも属性の跡が回の終わりまで残ります（[騎士の動きと効果音](騎士の動きと効果音.md)の「命中の反応」）。

## 敵の圧

騎士が自分から動いて画面を揺らす場面です。時刻は `src/game/rounds.ts` の一つの表（`ENEMY_MOVES`、`ENEMY_CHARGE_FROM_MS`、`ENEMY_SLAM_MS`）から取り、画面の揺れ、騎士の動き、音、床の見せ方が同じ時刻を見ます。

| 何が起きるか | 同時に | 順番に |
| --- | --- | --- |
| 騎士が足を踏み替える。画面が下へ4画素押され、低い足音 | 3.5秒 | 3.5秒 |
| 剣で盾を打ち鳴らす。画面が横に3画素震え、金属の音 | 9.5秒 | 9.5秒 |
| 剣を振り上げて溜める。画面が低く震え続け（0.5画素から2画素へ）、じわじわ寄り（1.02倍）、低いうなりが大きくなる | 30.2〜48秒 | 26.2〜40秒 |
| 振り下ろしの風切り（防御の回の確定） | 48秒 | 40秒 |
| 剣が床を打つ（確定の0.55秒後）。画面が下へ強く押され、傾き1.5度と寄り1.06倍が0.3秒で戻る。足元から赤熱した亀裂が走って回の終わりまで残り、塵が左右の端まで流れる。騎士の足元から衝撃波の歪みが広がる。重い衝撃の音 | 48.55秒 | 40.55秒 |

足踏みと盾打ちの音は、録音中でも鳴ります。「順番に」では一回目が声だけの回なので、唱えている最中に鳴ります。溜めのうなりは曲と同じ経路を通るので、マイクを使って声を受け付けている間は曲と一緒に下がります。「同時に」では防御の回の受付（30〜45秒）と重なるので下がり、「順番に」の防御の回は手だけなので下がりません（[騎士の動きと効果音](騎士の動きと効果音.md)の「効果音」）。

敵の斬撃の三日月は基準の1.4倍で、近づくほど画面の高さの4分の1まで広がります。敵の圧では閃光を足していません。控えめモードと「動きを減らす」設定では、揺れも反転も出しません。

防御の回の重い後処理（光のにじみ、色収差、歪み）は、床を打つ一撃の0.1秒前（「同時に」は48.45秒、「順番に」は40.45秒）から入ります。

騎士の側の動き（見上げる視点、視点そのものが動くこと、足踏みと盾打ちの姿勢、溜めの震え）は[騎士の動きと効果音](騎士の動きと効果音.md)にまとめています。倒れるときに視点へ近づく距離は、視点を近くした分だけ縮めてあります（0.15）。倒れた騎士は画面の中央付近に大きく映るので、実機で見て詰めるかどうかを決めてください。

## 確認したこと（2026年9月21日）

「同時に」だけだったころの確認です。

- そのときの単体の試験、型検査、配布用の生成は通りました（今の件数は[実装と確認の記録](実装と確認の記録.md)）。
- 開発用の環境（ソフトウェア描画）で、仮の時計を進めて画面写真を撮り、次を目で確かめました。弾が画面の四隅まで散ってから騎士へ集まること、命中の輪が左右の柱まで届くこと、術式が描いた場所に残ること、防御の回で床に亀裂が走り斬撃が大きくなること、とどめの光線が台形になること。発動の直前の0.08秒の暗転も残っています（写真で真っ暗な一枚が出たら、それです）。
- そのときのブラウザーの試験26件が、Macですべて通りました。音の並びの期待は、足踏み、盾打ち、風切り、床の一撃を含む形にしてあります。

## 実機で見てほしいこと（未確認）

- 揺れの大きさ。派手の設定でふつうの魔法の命中は約30画素、最大の設定で8連弾なら約60画素になります。大きすぎれば `presets.ts` の `shake` を下げてください。
- 弾が騎士から離れる向きに200〜400画素ほど動いてから寄る動きが「溜めてから撃つ」ように見えるか。見え方が悪ければ `release.ts` の `SWELL` を小さくしてください。
- 柱を照らす帯の濃さ、破片の量、横幅を超える輪の太さ。
- 溜めのうなりの音量（曲の3割）と床を打つ音の重さ。実際のスピーカーで聞いて合わせてください。
- 大きく描いた術式が案内文の枠に重なるとき。重なるなら `spell-layout.ts` の `SPELL_BOUNDS.bottom` を上げれば済みます。
- 命中の反転の一枚と、三段の止めが速い画面で不自然でないか。
- 「順番に」の時刻での見え方。溜めが11秒に縮んだときの震えと寄りの上がり方、とどめの回で62秒から76秒まで術式が移っていく見え方。
