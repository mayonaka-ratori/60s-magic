# 騎士の部位分けと立体化の指示

> **今の状態（2026年9月23日）：まだ作っていません。** 案A（部位に分けた画像）も案B（立体モデル）も、素材は無く、読み込む処理もありません。今の騎士は、アプリの中で基本の形を組み立てた立体です。どちらの案で進めるかは決めていません。

騎士の見た目を今より良くするための素材の作り方です。[大型バトル演出の提案](../大型バトル演出_全面更新の提案.md)の段階5にある「騎士を部位に分けた素材か、立体モデル1体」にあたります。二つの案を並べ、どちらを選んでも進められるように要件を書きます。

## 今の騎士の作り

今の騎士は外部の素材を使わず、アプリの中で角柱、円錐、半球を組み合わせて作っています（`src/render/knight.ts`）。画面に組み込む処理は`src/render/cast-scene.ts`にあります。

分かっていることをまとめます。置き換えの段取りは、ここに合わせます。

| 項目 | 今の作り |
| --- | --- |
| 組み立て | Babylon.jsの基本の形だけ。脚、腰布、胴、マント、兜と角、両腕、剣、盾、足元の影 |
| 部位の分かれ方 | 上半身、首（頭）、剣を持つ腕、盾を持つ腕を、それぞれ動かせる単位にしている |
| 姿勢 | 10の姿勢の角度を表にして、時間に応じて混ぜている。一回目の待機、ひるむ、構えを戻す、防御の回の構え、溜め、振り下ろし、弾かれる、弱点を見せる前屈、とどめの回の崩れ落ち、待機の息づかい。とどめの回では、肩の棘、盾、兜の角、胸当てが順に外れて落ちる |
| 大きさ | 角の先まで2.93m。足元を画面の高さの71.4%、兜の先を2%に置き、低い位置から少し見上げる |
| 視点 | 固定。背景の一枚絵（横と縦の比が1672対941）と同じ見え方になるよう、画面の幅に応じて画角を変える |
| 向き | 真正面だと板に見えるため、体を少しだけ（0.14ラジアン、約8度）振っている |
| 描き方 | 見えないcanvasに立体を描き、その絵を表のcanvasへ写すときに、吹き飛び、回転、白飛びの点滅、残像、輪郭の発光を重ねている |
| 当てる場所 | 胸の核の位置を毎コマ計算し、魔法の狙い先として渡している |

どちらの案を選んでも、この「描いた絵を写すときに効果を重ねる」仕組みはそのまま使えます。立体を組み立てている部分だけを差し替えます。

## 案A：画像を部位に分ける

生成した騎士の一枚絵（`public/art/ruins-knight-v1.png`。今のアプリでは使っていない）を、胴、頭、腕と剣、盾の4つの透過画像に分けます。アプリ側でそれぞれを別々に動かし、関節のように回します。立体モデルより手間が軽く、一枚絵の見た目の質をそのまま使えます。ただし、今の立体の騎士が持つ防御の回やとどめの回の動き（溜め、振り下ろし、前屈、部品の脱落、崩れ落ち）は、部位の画像を回すだけでは作りにくくなります。

### 作るもの

| ファイル | 中身 |
| --- | --- |
| `torso.png` | 胴。首から下、腰布と脚を含む。両腕、頭、盾は含めない |
| `head.png` | 兜と角、首まで |
| `sword-arm.png` | 剣を持つ腕（肩当てから手まで）と剣を一体で |
| `shield.png` | 盾と、盾を持つ腕 |

すべて次を守ります。

- 元になる画像は`public/art/ruins-knight-v1.png`の騎士です。同じ視点、同じ縮尺、同じ照明。
- 背景は透過。接地影、地面、背景、文字を含めない。
- 部位どうしの重なる部分は少し多めに残す。胴は肩の付け根まで、腕は肩当ての奥まで描く。隙間が見えるより、重なっているほうが良い。
- 4枚とも同じ寸法の画布に描く（例：2048×2048）。切り詰めない。こうすると、全部を同じ位置に重ねるだけで元の騎士に戻ります。

### 原点（回転の中心）の記録

部位を動かすには、「どこを軸に回すか」を決めた点が要ります。これを原点と呼びます。画像を作ったあと、次の4つの点の座標を測って記録します。

| 部位 | 原点に置く場所 |
| --- | --- |
| 胴 | 腰のまん中（帯の位置） |
| 頭 | 首の付け根 |
| 剣を持つ腕 | 肩の関節のまん中 |
| 盾 | 肩の関節のまん中 |

測り方。画像編集の道具（WindowsならペイントやGIMP、Macならプレビューや無料のGIMP）で画像を開き、その場所へカーソルを合わせて、画面の隅に出る座標（左上を0とした横と縦の画素の数）を読みます。読んだ数を次の形で`public/art/knight-parts-v1/origins.json`に書いて、画像と一緒に置いてください。

```json
{
  "canvas": { "width": 2048, "height": 2048 },
  "parts": {
    "torso": { "x": 1024, "y": 1180 },
    "head": { "x": 1024, "y": 620 },
    "sword-arm": { "x": 880, "y": 760 },
    "shield": { "x": 1170, "y": 770 }
  }
}
```

数字は例です。実際に測った値に置き換えてください。この一覧があれば、アプリ側は各部位を原点で回すだけで動かせます。

### 指示文（日本語）

部位ごとに1回ずつ、元の騎士の画像を添えて実行します。`【この部位】`の行を毎回書き換えます。

```text
用途：既存のゲーム画像から、同じ騎士の部位を切り出した透過画像を作る。あとで部位ごとに動かして使う。
入力画像は同一の騎士の参考です。デザイン、鎧の細部、傷み、色、照明を一切変えないでください。
出力：2048×2048の透過PNG1枚。背景は本当の透明。市松模様、地面、接地影、背景、文字、枠を描かない。
内容：【この部位】だけを描く。ほかの部位は描かない。
位置と大きさ：元の画像と同じ視点、同じ縮尺、同じ向き。画布の中での位置も元の画像と同じ場所に置く（切り詰めたり中央へ寄せたりしない）。
つなぎ目：隣の部位と重なる付け根は、隠れる分まで少し多めに描く。断面を平らに切らない。
禁止：デザインの変更、簡略化、絵柄の変更、光や魔法の効果の描き込み、文字、枠、複数の部位。
```

【この部位】に入れる言葉。

- 胴：`胴。首の付け根から下、胸当て、帯、腰布、脚、足まで。両腕、肩当て、頭、剣、盾、マントの外側を含めない`
- 頭：`頭。兜、兜の角、面覆い、喉当て、首の付け根まで`
- 剣を持つ腕：`画面の左側の腕。肩当て、上腕、肘当て、前腕、手、握りと鍔と刃を含む剣の全体`
- 盾：`画面の右側の腕と盾。肩当て、上腕、前腕、手、盾の全体（縁と中央の飾りを含む）`

### 指示文（英語）

```text
Use case: precise-object-edit and identity-preserve. The supplied image is the SAME dark iron knight; do not restyle, simplify or redesign anything.
Output: ONE transparent PNG, 2048x2048, with ACTUAL TRANSPARENT ALPHA. No checkerboard pixels, no ground, no contact shadow, no background, no lettering, no frame.
Content: draw ONLY [THIS PART]. Omit every other part of the knight.
Placement: identical camera, identical scale, identical orientation as the source image, and positioned at the SAME place on the canvas as in the source. Do not crop, do not recenter, do not resize.
Seams: where this part joins its neighbour, extend the art a little past the joint into the area that will be hidden. Do not cut a flat straight edge at the joint.
Constraints: preserve the ornate weathered iron armour exactly, keep the cool overcast lighting, no glow, no spell effects, no text, no extra parts.
```

`[THIS PART]`に入れる言葉。

- torso: `the torso: from the base of the neck down, breastplate, belt, armour skirt, legs and boots. No arms, no pauldrons, no head, no sword, no shield`
- head: `the head: crown-shaped helmet, horns, face guard, gorget, down to the base of the neck`
- sword arm: `the viewer-left arm: pauldron, upper arm, elbow guard, forearm, hand, and the complete long sword including grip, crossguard and blade`
- shield: `the viewer-right arm and shield: pauldron, upper arm, forearm, hand, and the whole engraved shield with its rim and central boss`

## 案B：立体モデルを用意する

騎士を立体のモデル（glTFという形式。ファイルの拡張子は`.glb`）で用意し、今の組み立てと差し替えます。作り込みの手間は大きいですが、向きを変えられる、影が正しく落ちる、動きを細かく作れるという利点があります。画像生成機能では作れないので、外部の素材を買うか、作れる人に頼むことになります。

### 要件

| 項目 | 求めるもの |
| --- | --- |
| 形式 | glTFの2.0、1ファイルにまとまった`.glb` |
| 三角形の数 | 3万〜8万。10万を超えると、展示用のノートPCで60コマ毎秒を保てないおそれがある |
| 画像の大きさ | 色や表面の凹凸を表す画像は2048×2048まで。枚数は4枚まで |
| 材質 | 金属と粗さで表す方式（PBR）。Babylon.jsがそのまま読める標準のもの |
| 身長 | 角の先まで2.93m。足の裏を原点（高さ0）に置く |
| 向き | 正面が奥（Babylon.jsの+Z）を向く。今の実装で体を少し振る処理をそのまま使う |
| 単位 | 1単位＝1メートル。拡大縮小は1倍で書き出す |
| 剣と盾 | 別々に動かせるよう、骨（あとで説明します）に付けて分ける |

### 動き

3つの動きを付けます。この指示文を書いたときの騎士の姿勢（待機、ひるむ、構えを戻す）と同じ役割です。今の騎士は防御ととどめの回の動き（溜め、振り下ろし、前屈、崩れ落ち、部品の脱落）も持っているので、立体モデルに置き換えるなら、その分の動きも要ります。

| 名前 | 長さ | 中身 |
| --- | --- | --- |
| `idle` | 3〜4秒、繰り返せる | 待機。呼吸で胸と肩がゆっくり上下し、剣先がわずかに揺れる。足は動かさない |
| `hit` | 0.6秒 | 被弾。胸と肩が奥へのけぞり、頭がすくみ、剣を持つ手が少し下がり、盾が外へ傾く。足は地面から離さない |
| `stagger` | 1.2秒 | よろめき。上体が大きく傾き、一歩ぶん沈んでから戻る。倒れきらない |

3つとも、開始と終了の姿勢がつながるようにします。`idle`は繰り返して途切れないこと。

### 骨の名前

骨とは、モデルの中で関節の役割をする目印です。アプリから直接つかんで動かす骨だけ、名前を決めておきます。

| 名前 | 場所 |
| --- | --- |
| `root` | 足元、高さ0のまん中 |
| `hips` | 腰 |
| `spine` | 背骨のまん中 |
| `chest` | 胸。魔法を当てる狙い先にも使う |
| `head` | 頭 |
| `arm_sword` | 剣を持つ腕の肩 |
| `hand_sword` | 剣を持つ手。剣はこの骨に付ける |
| `arm_shield` | 盾を持つ腕の肩 |
| `hand_shield` | 盾を持つ手。盾はこの骨に付ける |

ほかの骨の名前は自由です。`chest`は必ず入れてください。今の実装は胸の位置を魔法の狙い先に使っているので、この骨があればそのまま置き換えられます。

### 著作権と展示での利用条件

素材を買うか、人に頼むときは、次をすべて満たすものだけを使います。使った素材の名前、入手先、条件、表記の文を`docs/実装と確認の記録.md`に書き残してください。

- 商用で使える（展示は入場料の有無にかかわらず商用とみなして選ぶ）。
- 改変できる（大きさや材質を調整するため）。
- ゲームやアプリに組み込んで配布できる。
- 公の場での上映、展示ができる。
- 表記が必要なら、その文をそのまま結果画面に出せる（音素材と同じ仕組みを使います。[音素材の入れ方](../音素材の入れ方.md)を参照）。
- 実在の作品の登場人物に似せたもの、公式の素材を無断で変換したものは使わない。

### 置き換えの段取り

1. モデルを`public/art/knight-v1.glb`に置く。
2. Babylon.jsでglTFを読むための追加（`@babylonjs/loaders`）を入れる。版は今の`@babylonjs/core`と合わせる。
3. `src/render/knight.ts`の、形を組み立てている部分だけをモデルの読み込みに差し替える。姿勢の混ぜ方は、角度の指定から動きの再生へ置き換える。
4. 写すときに重ねている効果（吹き飛び、白飛び、残像、輪郭の発光）はそのまま使う。
5. 胸の狙い先は`chest`の骨の位置から取る。
6. 読み込みに失敗したときは、今の組み立てた騎士へ戻す退避の道を残す。展示の当日に画面が消えないようにするためです。

## 置き場所と受け入れの確認

### 案Aの場合

`public/art/knight-parts-v1/`というフォルダーを作り、その中に置きます。

```
public/art/knight-parts-v1/
  torso.png
  head.png
  sword-arm.png
  shield.png
  origins.json
```

確認すること。

1. 4枚とも透明があるか。ブラウザーで1枚ずつ開き（`http://localhost:5173/art/knight-parts-v1/torso.png`など）、背景が透けて見える。
2. 4枚とも寸法が同じか（例：2048×2048）。
3. 4枚を重ねると元の騎士に戻るか。隙間や二重の線が出ない。画像編集の道具で4枚を重ねて確かめる。
4. 付け根が平らに切られていないか。腕の肩側、頭の首側に少し余分があるか。
5. 接地影や地面が混ざっていないか。
6. 明るい部分が真っ白につぶれていないか。
7. `origins.json`の4つの点が、実際の関節の位置と合っているか。

### 案Bの場合

`public/art/knight-v1.glb`として置きます。

確認すること。

1. ファイルが1つにまとまっているか（画像が別ファイルに分かれていない）。
2. 三角形の数が8万以下か。
3. 高さが2.93mで、足の裏が高さ0にあるか。
4. `idle`、`hit`、`stagger`の3つの動きが入っているか。
5. `chest`という名前の骨があるか。
6. 剣と盾が手の骨に付いていて、腕を動かすと一緒に動くか。
7. 利用条件の文書（ライセンス）が手元にあり、商用と展示が許されているか。

確認のしかた。`.glb`は中身を目で見るのが難しいので、Babylon.jsが公式に用意している確認用の画面（<https://sandbox.babylonjs.com/>）にファイルを放り込むと、形、動きの一覧、三角形の数をその場で見られます。外部のサイトへ送ることになるので、条件が厳しい素材のときは代わりにBlenderなど手元の道具で開いてください。

### 共通

`npm run setup:assets`は手の認識に使うファイルを用意するコマンドで、これらの素材とは関係ありません。`public/art/`に置くだけで開発用のサーバーから見えます。素材ファイル本体をGitに入れるかどうかは、利用条件しだいです。条件が「再配布は不可」なら入れず、置き方だけを文書に残します。

読み込む処理はまだありません。素材を置いたあと、案Aなら部位を重ねて動かす処理、案Bならモデルを読み込んで動きを再生する処理を作ります。
