# 着弾のコマ絵の生成の指示

魔法が騎士に当たった瞬間の爆発を、少しずつ形の違う絵を並べて作ります。並べた絵を順に切り替えると、爆発が動いて見えます。[大型バトル演出の提案](../大型バトル演出_全面更新の提案.md)の段階5で挙げた素材の2点目です。

ユーザーの手元にある画像生成機能で作ります。この文書の指示文をそのまま貼って使えます。まだ読み込む処理はありません。画像を置いたあとに読み込みの実装を作ります。

- 置き場所：`public/art/impact-sprite-v1.png`
- 用途：命中の0.4〜0.6秒。騎士の胸のあたりに重ねる。属性の色付けはアプリ側で行う。

## 作るもの

| 項目 | 決めたこと |
| --- | --- |
| 1コマの寸法 | 256×256 |
| コマ数 | 16（4×4の格子）。難しければ8（横一列、2048×256、または4×2） |
| 並べ方 | 左上から右へ、行を折り返して下へ |
| 画像全体の寸法 | 16コマの格子なら1024×1024。8コマの横一列なら2048×256 |
| 背景 | 黒一色。または透過。どちらでもよいが、画像の中で混ぜない |
| 色 | 白から淡い水色まで。強い色を付けない |

背景を黒にするのは、アプリ側で「加算合成」という重ね方をするためです。黒い部分は重ねても何も足されないので、切り抜かなくても背景に溶けます。透過でも扱えます。

属性（炎、氷、雷、風、光、闇）ごとの色は、この白い絵にアプリ側で色を掛けて出します。素材の時点でオレンジや青に染めてしまうと、色を変えたときに濁ります。白から淡い水色までに留めてください。

## コマの順

1コマ目から16コマ目まで、次の順で変わります。8コマのときは同じ流れを半分の数でたどります。

| コマ | 見えるもの |
| --- | --- |
| 1〜2 | 中心の小さく鋭い閃光。周りはほぼ何もない |
| 3〜5 | 一気に膨らむ。丸い光の玉と、外へ飛ぶ細い火花 |
| 6〜9 | いちばん大きい。輪が広がり、中心が抜けはじめる |
| 10〜13 | 光が薄れ、煙と細かい粒が残る |
| 14〜16 | ほとんど消える。最後のコマは真っ黒（透過なら完全に透明）に近い |

各コマは自分の枠の中に収まり、隣の枠へはみ出さないようにします。枠の線や区切り線は描きません。

## 避けること

- 文字、数字、枠線、区切り線、透かし。
- コマごとに向きや中心がずれること。中心はどのコマも枠のまん中。
- 強いオレンジや赤。写真の炎の切り抜き。
- 最後のコマにまだ明るい光が残っていること。

## 指示文（日本語）

```text

出力：1024×1024の画像1枚。256×256のコマを4行4列の格子に並べる。合計16コマ。区切り線、枠、文字、数字、透かしを描かない。
背景：完全な黒（#000000）一色。
色：白から淡い水色まで。中心がいちばん明るく、外へ行くほど暗い。オレンジや赤に寄せない。
コマの順：左上から右へ、行を折り返して下へ進む、1つの爆発の連続した変化。
　1〜2コマ目：中心の小さく鋭い閃光のみ。
　3〜5コマ目：急に膨らむ光の玉と、外へ飛ぶ細い火花。
　6〜9コマ目：最大。広がる輪と、中心が抜けはじめる。
　10〜13コマ目：光が薄れ、煙と細かい粒が残る。
　14〜16コマ目：ほとんど消える。16コマ目はほぼ真っ黒。
各コマの爆発は自分の枠の中心にあり、枠の外へはみ出さない。コマごとに中心や向きがずれない。すべて同じ縮尺。
質感：高精細なゲームのエネルギー爆発。写真の炎の切り抜きにしない。漫画調にしない。
```

## コマ絵がうまく作れないときの代わり

画像生成は、きれいに並んだコマ絵を苦手とすることがあります。並びが崩れる、コマごとに中心がずれる、区切り線が出る、といったときは次の二つで代用できます。

**1枚の爆発を拡大と縮小で動かす。** 一番大きく広がった瞬間の爆発を1枚だけ作ります（512×512、黒背景、白から淡い水色）。アプリ側で、小さく明るい状態から大きく薄い状態へ、0.4秒かけて拡大しながら薄くします。コマ絵ほど細かい煙の動きは出ませんが、命中の手応えは十分に出ます。この場合の置き場所は `public/art/impact-burst-v1.png` です。

指示文の要点だけを変えます。

```text
出力：512×512の画像1枚。黒背景。広がりきった瞬間のエネルギー爆発を1つだけ、中心に置く。外へ伸びる細い火花と、薄い輪。白から淡い水色。文字、枠、区切り線を描かない。
```

**複数枚を別々に作って並べる。** 「膨らむ瞬間」「最大」「煙が残る」のように段階ごとに4〜8枚を1枚ずつ作り、あとで横一列につなげます。つなげる作業は画像編集の手間がかかりますが、1枚ごとの質は上がります。この場合は、どの枚も同じ寸法（256×256）、同じ中心、同じ黒背景で作るよう、毎回の指示文に書いてください。

## 置き場所と受け入れの確認

できた画像を `public/art/impact-sprite-v1.png` として置きます（代わりの案を使ったときは `impact-burst-v1.png`）。作り直したときは `-v2` のように数字を上げます。

確認すること。

1. 寸法が1024×1024（8コマの横一列なら2048×256）か。1コマがちょうど256×256に割り切れる。
2. コマ数が予定どおりか。画像を開いて格子を数える。
3. 背景が本当に真っ黒か。黒のつもりで暗い灰色になっていると、加算合成のときに画面全体がうっすら明るくなる。ブラウザーで開いて周りの黒と見比べる。
4. どのコマも爆発が枠の中に収まり、隣へはみ出していない。中心がずれていない。
5. 明るい部分が真っ白につぶれ、形が分からなくなっていない。中心だけが白で、周りに階調が残っている。
6. 区切り線、文字、数字が入っていない。
7. 最後のコマがほぼ黒（または完全に透明）になっている。

確認のしかた。開発用のサーバーを動かし（`npm run dev`）、ブラウザーで `http://localhost:5173/art/impact-sprite-v1.png` を開きます。画像だけが大きく表示されるので、格子の並びと黒の濃さを目で確かめられます。

`npm run setup:assets` は手の認識に使うファイルを用意するコマンドで、この画像とは関係ありません。画像は `public/art/` に置くだけで見えます。

読み込む処理はまだありません。画像を置いたあと、命中に合わせてコマを順に切り替える処理と、属性ごとに色を掛ける処理を作ります。
