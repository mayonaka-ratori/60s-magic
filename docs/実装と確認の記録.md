最終更新：2026年9月20日。対象は最初の40秒（一回目の魔法と防御の回）です。何を作ったかは [README](../README.md) と [動きの詳細](動きの詳細.md)、測った値は [確認に使うPC](確認に使うPC.md) にあります。

## 今の状態を一言で

一回目の魔法は、マウスと合成音声で、線を描いて唱えてから七つの雷が発動するまでをMacの実機で通しで確認できています。防御の回（24〜40秒）は2026年9月20日に作りましたが、**実機ではまだ一度も動かしていません**。実際の人の声、実際の手の追従、Jevとの実通信、初見の人による確認も未実施です。

## 防御の回（2026年9月20日に追加）

24秒から40秒までを作りました。何を作ったかと、確認できていないことは [防御ととどめの設計](防御ととどめ_画面と流れの設計.md) の「進み具合」にまとめています。要点だけ書くと、狙いの印、囲ったときの返事、描いた線から作る盾、詠唱で変わる三つの止め方、敵の一撃、騎士の8姿勢と弱点、二つの魔法を並べる結果画面です。

**実機で最初に見てほしいところ。**

1. 24秒に出る赤い印が、囲みやすい大きさと位置か。画面の高さの62%に置いています。
2. 印を囲んだ瞬間に、印が赤から属性の色へ変わるか。その変化に気づけるか。
3. 囲えなかったときに、線が印の前へ動くのが分かるか。
4. 35.4秒の受け止めに手応えがあるか。「弾き返せ」と唱えたときに、一撃が騎士へ戻るのが見えるか。
5. 39秒に胸当てが外れて弱点が出るのが分かるか。
6. マイクを使うとき、防御の回の声を拾えているか（21.5秒につなぎ直しています）。

この作業環境は1秒に1コマしか描けないため、線を引いても点と点の間が350ms以上空いて一本になりません。囲みの動作はこの環境では確かめられず、単体試験でだけ確認しています。

合成音声はMacの読み上げ機能（Eddy）で作っています。「雷よ」が「カメナリよ」「亀なり」と書き起こされますが、雷として受け付けるようにしたので魔法は一致します。実際の人の声で同じになることは未確認です。結果は `.local-speech/test-report.json` と `.local-speech/browser-test-report.json` に置き、Gitには含めません。

`npm test` と `npm run build` は防御の回を足したあとの結果です。それ以外の行は、24秒だったころの記録です。

ブラウザー試験は、40秒の流れと新しい記録の形に合わせて書き直しました。この作業環境は1秒に1コマしか描けないため走らせられていないので、**Macで一度通してください**。`npm run test:browser` です。防御の回の試験では、印を囲んで氷の盾を作り、弾き返すところまでを見ています。

### 実機で遊んだ記録（Mac）

- マウスと合成音声で24秒を通し、17.0秒に発動。
- カメラで24秒を通したとき、平均44.5fps。手が画面の端に出ると見失い、20筆で61点しか取れない回があった。これを受けて手の認識のしきい値を下げ、350msまでの途切れは同じ筆として続けるようにした。直した後の追従は未確認。
- 音声認識（`kotoba-v2.0-mlx`、MacのGPU）は13秒ほどの声で一回約1.25秒。以前は最後の結果を待つ時間が足りず捨てていたため、待ちを1.4秒、打ち切りを15.4秒にし、12.6秒以降は途中の認識を始めないようにした。直した後、人の声で `finalDelivered` が `true` になるかは未確認。
- Jevは接続情報を設定した回があり、14.68秒に返事が届いて採用された（一回だけ）。

### Windows（元の開発環境、NVIDIA RTX 4070 SUPER）

`kotoba-v2.0` で合成音声一回分の認識が約110〜125ms。平均59.75fps、フレーム間隔の99パーセンタイル16.9ms、発動17.009秒。今日の変更後は測り直していません。

## 2026年9月20日に直したこと

- Macでブラウザー試験が全部落ちる原因（Windows専用の描画設定）を直した。
- 完成した術式の線を太くし、外側に帯を足して、暗い背景でもはっきり見えるようにした。
- 手の認識のしきい値を下げ、筆を分ける途切れを350msにした。
- 最後の声を待つ時間と打ち切りを広げ、終了直前の無駄な認識をやめた。
- 「かみなり」の聞き違い（カメナリ、亀なり、神鳴）を雷として受け付けるようにした。
- 手の認識をまずGPUで動かし、使えなければCPUへ戻すようにした。カメラの処理時間を記録に残す。
- 聞き取りの書き方の揺れを辞書へ寄せる仕組み（`corrections`）を入れた。
- 音声認識をMacのGPU（mlx-whisper）で動かせるようにした。
- 確認用の表示を `?dev=1` のときだけ出すようにした。
- 文字が重なる画面を直した。

## まだ確認していないこと

- 実際の人の声での聞き取りの精度と、最後の言葉が間に合う割合。記録の `rawTranscript` と `finalDelivered` で見る。
- 実際の手の追従。しきい値を下げたあとの取りこぼしと、GPUで動いたか（記録の `diagnostics.camera.delegate`）。GPUがうまくいかなければ `?hands=cpu` で戻せる。
- 音声認識・手の認識・画面の描画が全部GPUを使うことによる取り合い。
- Jevとの実通信を何回も試したときの安定性。一回だけ採用を確認。
- Google Cloudとの実通信。接続情報が未設定。
- 初見の5人による「自分の魔法を放った」という実感。手順は [人に試してもらう手順](人に試してもらう手順.md)。
