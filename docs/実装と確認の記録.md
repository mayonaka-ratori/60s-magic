## 防御の回（2026年9月20日に追加）

24秒から40秒までを作りました。何を作ったかと、確認できていないことは [防御ととどめの設計](防御ととどめ_画面と流れの設計.md) の「進み具合」にまとめています。要点だけ書くと、狙いの印、囲ったときの返事、描いた線から作る盾、詠唱で変わる三つの止め方、敵の一撃、騎士の8姿勢と弱点、それぞれの魔法を並べる結果画面です。

**実機で最初に見てほしいところ。**

1. 24秒に出る赤い印が、囲みやすい大きさと位置か。画面の高さの62%に置いています。
2. 印を囲んだ瞬間に、印が赤から属性の色へ変わるか。その変化に気づけるか。
3. 囲えなかったときに、線が印の前へ動くのが分かるか。
4. 35.4秒の受け止めに手応えがあるか。「弾き返せ」と唱えたときに、一撃が騎士へ戻るのが見えるか。
5. 39秒に胸当てが外れて弱点が出るのが分かるか。
6. マイクを使うとき、防御の回の声を拾えているか（21.5秒につなぎ直しています）。

この作業環境は1秒に1コマしか描けないため、線を引いても点と点の間が350ms以上空いて一本になりません。囲みの動作はこの環境では確かめられず、単体試験でだけ確認しています。

## とどめの回と魔導書（2026年9月20日に追加）

とどめの回（40〜60秒）と、60秒からの魔導書（結果画面）を作りました。**実機ではまだ一度も動かしていません。** 単体の試験は通っています。

魔導書は、左に最後の術式、右に魔法名（ふりがな付き）、属性と用途の札、詠唱の一文、持ち帰りの場所、確認番号、保存の状態の一行、下に三つの魔法を絵つきで並べる形にしました。縦長の画面では上から順に積みます。並べる三件は保存する記録から作るので、画面に出るものと保存したものが必ず同じになります。

持ち帰りは下ごしらえだけです。公開ページがまだ無いので、QRの場所には「持ち帰りの準備中」と出し、嘘のQRは出しません。保存の状態の一行は「この画面でだけ見られます」です。届いていないものを「登録しました」とは書きません。遊んだ記録（確認番号、三件のレシピ、術式の点列、詠唱の文字、引き継いだ形）は、魔法が確定するたびにこのPCのブラウザーの中へ残します。カメラの映像と声そのものは残しません。保存先を使えない環境では、保存できなかったことを覚えておくだけで、画面は止まりません。

確認番号は6桁の数字です。遊んだ人が持ち帰るものではなく、係員がどの回の記録かを探すための番号です。保存済みの番号と重ならないよう作り直します。

とどめの見せ方（視界を通る術式、輪、多段、直撃、スロー）、騎士の崩れ落ち、体力を0にする段、とどめの音は別途作っています。

**実機で最初に見てほしいところ。**

1. 魔法名が大きすぎず小さすぎないか。ふりがなが読めるか。
2. 下の三件の絵で、一回目・防御・とどめの違いが分かるか。
3. 確認番号が、離れた場所から読めるか。
4. 60秒の魔導書が出るまでに、画面のエラーが出ないか。

## 2026年9月20日に直したこと

- Macでブラウザー試験が全部落ちる原因（Windows専用の描画設定）を直した。
- 完成した術式の線を太くし、外側に帯を足して、暗い背景でもはっきり見えるようにした。
- 手の認識のしきい値を下げ、筆を分ける途切れを350msにした。
- 最後の声を待つ時間と打ち切りを広げ、終了直前の無駄な認識をやめた。
- 「かみなり」の聞き違い（カメナリ、亀なり、神鳴）を雷として受け付けるようにした。MacのGPUの認識（手掛かりなし）では「カメラリ」「かめなり」のようにさらに崩れることがあるので、その書き方も足した（実際の記録に「カメナリを7つに分かれろ」と「カメラリオ」があった）。
- 手の認識をまずGPUで動かし、使えなければCPUへ戻すようにした。カメラの処理時間を記録に残す。
- 聞き取りの書き方の揺れを辞書へ寄せる仕組み（`corrections`）を入れた。
- 音声認識をMacのGPU（mlx-whisper）で動かせるようにした。
- 確認用の表示を `?dev=1` のときだけ出すようにした。
- 文字が重なる画面を直した。

## 2026年9月20日に足した演出（大型バトル演出の全面更新）

調査と提案は [大型バトル演出：全面更新の提案](大型バトル演出_全面更新の提案.md)、部品ごとの説明は [演出のバリエーション：実装](演出のバリエーション_実装.md)にあります。

- 色の組と派手さを設定として切り出し、控えめ、派手（既定）、最大の3段階にした。`?preset=` で選べる。演出は蓄積、放出と飛翔、命中と余韻の部品に分かれている。
- 描いている最中に言葉と動きへ反応する。属性の言葉でその色の粒、確定前は候補の色、個数の言葉で光点。筆を置いた輪、速い線の火花、閉じた線の一周、声の脈動。線と言葉の量で蓄積が濃くなる。二つ目の属性語は飾り色になる。
- 時計を一つにして、命中の停止で騎士も術式も止まる。揺れは衝撃の強さで減る向き付きで、傾きと拡大も少し混ぜる。命中で寄る。放出の直前に一瞬の暗転。溜めで背景の彩度が落ちる。
- 閃光、ビネット、グレイン、暗転はHTMLの層で出す。閃光は立ち上がり速く戻り遅く、上限0.85（2026年9月21日に0.7から上げた）。全画面の明滅は放出と命中の2回だけで、雷の明滅も毎秒3回以下。
- 「演出を控えめにする」ボタンを開始画面とプレイ中に置いた。`?calm=1` と「動きを減らす」設定が優先。控えめでは揺れ、傾き、停止、色のずれが0、閃光は3分の1。
- 騎士は白飛び（白、属性色、白の三段が一続き）、吹き飛びと回転、残像、輪郭の発光、反応の段階化（怯み、よろめき、崩れ）。体力は本体と遅れて追う残りの二層。
- 最前面の合成用のBabylonシーンで、ブルーム、端ほど強い色収差、衝撃波の歪みをかける。後処理は16.9〜21秒だけ。WebGLが使えないときと `?composite=0` では元の層のまま。fpsが55を下回るとブルームを切り、24fps未満が続くと合成を止める。
- 魔法は芯を白、縁を属性色に統一。属性ごとの消え方（炎は煙、氷はかけら、雷は瞬断、風は流れる、光は減速、闇は吸い込み）と地面の跡。二属性は増幅、爆発、持続の三型。連弾は80ms間隔で届き最後だけ特大。
- `?view=effects` で左右に設定を並べ、属性、形、用途、個数、言葉、入力の量、時刻を変えて見比べられる。
- 素材の生成指示（カットインの立ち絵、着弾のコマ絵、騎士の部位分けと立体化）を `references/` に用意した。素材はまだ置いていない。

## 2026年9月20日のコード全体のレビューで直したこと

- 音声認識の接続で `Origin` が `null` という文字のとき、サーバーごと止まっていたのを直した。読めない値は接続を断るだけにする。この作業環境で、`Origin: null` を送ってもサーバーが生きていることを確認した。
- `npm run test:chants` がWindows専用のPythonの場所を決め打ちしていてMacで動かなかったのを、他の道具と同じ決まりに合わせた。Macで最後まで動くことを確認した（2026年9月20日）。合成音声14件のうち魔法の種類まで一致したのは5件で、難しい言葉（雷霆、氷晶、霹靂など）は聞き取れていない。手掛かりの語を入れる前後で結果が同じだったのは、比較の道具が「前」にも同じ14語を渡していたためで、認識の方式の問題ではなかった。手掛かりなしと手掛かりありを比べるように直した。MacのGPUで動かす方式（mlx-whisper 0.4.3）は、渡した語を最初の30秒の解読の前置きに入れることを、その中身を読んで確認した。直した比較をMacで走らせた結果、mlxでは手掛かりを渡した方が悪かった（魔法まで一致が6件から5件へ。文が途中で切れたり空になったりする）。そのためMacのGPUで動かすときは手掛かりを渡さない初期値にした（`LOCAL_SPEECH_HINTS`）。難語（雷霆、氷晶、霹靂、紅蓮）はどちらでも聞き取れていない。直した後の本編での確認は未実施。
