# 演出コードのレビュー結果

2026年9月20日、演出に関わるコード全体（部品、画面全体の効果、言葉と動きへの反応、合成の後処理、騎士、体力表示、音、試験、文書）を4人で分担して読み、コードを動かして確かめた指摘をまとめたものです。ゲームがまだ60秒で「同時に」だけだったころのレビューです。今の秒数は `src/game/rounds.ts` の表にあります。

指摘はほぼすべて同じ日のうちに直しました。2026年9月23日に今のコードと照らし、直したものと残っているものを分け直しています。細かい直し方はGitの履歴にあります。

## 残っているもの

| 場所 | 中身 |
| --- | --- |
| `src/effects-lab.ts` | 見比べ画面に合成の後処理（光のにじみ、色収差、歪み）が無い。閃光や縁の暗さなどのHTMLの層は足してあるが、後処理の分だけ本編と見え方が違う |
| `src/render/magic.ts`、`src/render/effects/screen.ts` | 画面の揺れだけ、命中の停止を含まない生の時刻で決まっている（衝撃波などは停止を含む時刻）。揃えると見た目が変わるため見送った |
| `src/render/overlay.ts` | 層を受け取る型に、使っていない `knight` と `spell` が残っている。呼ぶ側がまとめて渡すので受け取れるようにしてあり、使わないことはコードに書いてある。実害は無い |

## 直したもの

### 重いもの（高）

- 連弾の2発目以降が途中で止まって騎士に届かなかった。進み具合の頭打ちをやめた（`release.ts`）。
- 連弾の体力の減りが弾の届く時刻とずれ、最後の1発で減らなかった。段の時刻を弾と同じ `hitDelay` から作る（`health-bar.ts`）。
- 描いている間の候補の色と確定の色が逆だった。候補の色も最初に言った属性語にそろえた（`live-words.ts`）。
- 認識が伸びるたびに言葉の反応がやり直されていた。言葉ごとに初めて現れた時刻を覚えて使う（`live-words.ts`）。
- 線を引いて戻すだけで「閉じた輪」と判定していた。囲んだ面積の条件を足した（`strokes-math.ts`）。
- 控えめモードが騎士に届かず、白飛びが消えなかった。白飛びを出さず、残像と輪郭を3分の1にする（`knight.ts`、`cast-scene.ts`）。
- 控えめモードでも光のにじみが命中で5倍になっていた。控えめでは1.6倍まで（`composite.ts`）。
- 色のずれが二重にかかっていた。合成が動いている間は演出の描画面の中の色ずれを飛ばし、合成なしでも命中から0.2秒に絞った（`magic.ts`）。
- 命中で粒の上限を超えていた。上限を派手900、最大1500に上げ、空きの探し方を速くした（`presets.ts`、`particles.ts`）。
- 文書に体力表示の試験があると書いてあったのに無かった。`tests/health-bar.test.ts` を足した。

### 次に重いもの（中）：入力の量と言葉

- 即時の反応と確定で語彙が食い違っていた。`spell-words.ts` の一つの表を両方が読む。
- 認識が語を前に足すと同じ言葉の反応がもう一度出た。言葉の番号を発話と語と出現回数で作る（`live-words.ts`）。
- 途中結果が短くなると入力の量が下がった。発話ごとに見た最大の文字数を使う（`input-amount.ts`）。
- 毎コマ全文を読み直していた。発話が変わったときだけ計算し直す（`main.ts`）。
- 音が入力の量を見ていなかった。音の厚みにも入力の量を渡す（`cast-audio.ts`）。
- 騎士の反応の強さに入力の量を渡していなかった。渡すようにした（`cast-scene.ts`）。
- 入力の量が停止、暗転、揺れに二重に効いていた。派手さ（`intensityOf`）の一か所にまとめた。
- 控えめモードが部品に届いていなかった。部品へ渡し、粒の数と脈の速さを抑える（`frame.ts`）。

### 次に重いもの（中）：合成と層

- `?scale=` にとても小さい値を入れると固まった。下限0.5を付けた（`composite.ts`）。
- 山場の最中に合成をやめる判定が働いた。山場では判定を止め、先に光のにじみを切る段を挟む。
- WebGLの文脈が失われると静止画が最前面に残った。元の層へ戻す。
- 作成に失敗したときに後片付けをしていなかった。作りかけを解放する。
- なめらか化の指定が二重だった。一つにした。
- 背景の板だけ表示の大きさで作られ、ぼけていた。描画の細かさで作る。
- 縁を暗くする層が二重だった。遊んでいる間は固定の層を半分にして一本化した（`style.css`、`overlay.css`）。
- 合成が0秒からずっと働いていた。一回目の確定の0.5秒後から0.3秒かけて重ねる（`?composite=always` なら0秒から見せる）。
- 後処理が一コマで切れて明るさが段になった。手前0.3秒で光のにじみを0へ落としてから切る。
- 閃光の間隔の決まりが、消えた後にしか効かなかった。光り始めから0.34秒は次を上げない（`overlay.ts`）。
- 見比べ画面に閃光などの層が無く、つまみを戻すと固まった。HTMLの層を足し、描き直しを120コマまでにした（後処理が無いことは上の「残っているもの」）。

### 次に重いもの（中）：部品と騎士

- 粒を出すたびに新しいものを作っていた。使い回す（`particles.ts`）。
- 背景を暗くするグラデーションを毎コマ作っていた。作り置きにした（`magic.ts`）。
- 最大の設定で派手さが常に上限に張り付いた。設定ごとの倍率と底上げで出す（`presets.ts`）。派手でふつうの魔法が1.9になる点は前と同じ。
- 1回目と2回目以降で粒の散り方が違った。作り始めも同じ種にした（`magic.ts`）。
- コマ落ちで命中の火花が変わった。放出と命中の先頭で乱数の種を固定する（`magic.ts`）。
- 火花の線の長さに上限が無かった。上限を付けた（`frame.ts`）。
- 描く動きの覚え書きが見比べ画面の2枚で共有されていた。画面ごとに持ち、やり直しで消す（`strokes.ts`、`magic.ts`）。
- 騎士の輪郭の光が縁取りに見え、重かった。半分の大きさで1回だけ重ねる（`knight.ts`）。
- 騎士の置き方の計算が2か所に写されていた。`knightTransform` 一つにまとめた。
- 見た目の設定と控えめモードが騎士に届いていなかった。騎士へ渡す（`knight.ts`）。
- 体力表示だけ命中の停止中に先走った。停止を含む時刻で動かす（`health-bar.ts`）。

### 小さいもの（低）

- 効いていない代入や計算、使っていない引数と偽の部品を消した。
- 二属性の色が一部で無視されていた。放出の輪と線にも二色目を使う。
- 線を描く道具に芯の色の引数を足し、同じ計算の重複（`smooth`）をまとめた。
- 式の中の固定値（光の本数、粒の数、秒数など）に名前を付けて先頭へ出した。
- 模様を作る `noise` の引数が足し算で重なっていた。重ならない作りにした（`release.ts`、`impact.ts`）。
- 合成の慣らしの間に騎士の板を間引いて貼っていた。見せている間は毎コマ貼る（`composite.ts`）。
- 歪みの後処理の差し込み順が光のにじみの入り切りで変わりえた。組み直すたびに最後へ入れ直す（`composite.ts`）。
- 合成の描画面の目印（`dataset.on`）に初めの値が無かった。作った直後に隠す処理で `false` を入れる（`composite.ts`）。
- 確認用の記録の合成の項目の意味が分かりにくかった。項目ごとに説明を付けた（`composite.ts` の `report`）。
- 見比べ画面で騎士を片付けていなかった。離れるときに片付ける（`effects-lab.ts`）。
- 文書の件数や時刻の食い違いを直した。
- 試験を足した。弾の位置（`bodyPoint`）、往復の線の判定、即時の反応と確定の一致、層の変形、合成の設定の下限、体力表示、ブラウザーの試験での合成の目印。

## 問題なしと確かめたこと（2026年9月20日）

- 画面全体の効果（`screen.ts`）は時刻だけで決まる純粋な計算で、控えめモードで残る効果はなく、停止は二重にかからない。
- 全画面の閃光は、光り始めから0.34秒は次を上げない決まりがあり、1秒に3回を超えない。雷の明滅は毎秒3回。
- `knightPose` は純粋な計算。`Math.random` はリポジトリ全体で使っていない。
- 派手さを変えても音の時刻は変わらない。音量は圧縮器を通るので派手さ最大でも歪まない。
- `speech-book.ts` の `live()` は `snapshot()` と `freeze()` に触れていない。
- 描く動き、言葉、閃光、二属性の試験は振る舞いを確かめており、二属性の表は15組すべて実装と一致。

## 実機で確かめる必要があるもの

どれもまだ確かめていません。

- 合成への切り替わり（一回目の確定の0.5秒後から0.3秒かけて重ねる。「同時に」は21.5秒、「順番に」は17.5秒）が滑らかか。明るさが跳ねたり二重に見えたり、1〜2コマ真っ暗になったりしないか。後処理の切り際で明るさが段にならないか。
- 合成をやめる目安（90コマの慣らしのあと、24fps未満が60コマ続いたら）が、最初の読み込みで誤って働かないか。
- 騎士の輪郭が命中後0.6秒、縁取りでなく淡い光に見えるか。弾が胸に当たるか。停止の間に体力の帯も止まるか。`?preset=max` と `?preset=calm` で崩れ方が変わるか。
- 最大の設定で単発と連弾の差が出るか。
- 締め切りから余韻までの縁の暗さ。右上の残り時間と下の案内が読めるか。
- `?view=effects` で左右に閃光、縁の暗さ、ざらつき、暗転が出るか。つまみを戻しても固まらないか。
- 飛んでいる雷の形が毎秒24回変わる見え方。停止の間に揺れだけ進む見え方。
- 最大の設定、8連弾、入力の量1のときの、蓄積の粒の数と命中直後の描画の重さ。
